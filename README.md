# SBS 라디오 참여 도우미

이 PC에서만 돌아가는 SBS 라디오(파워FM·러브FM·고릴라M) 참여 도구입니다.

- **청취 시작 한 번**: 첫 화면의 **▶ 청취 시작**을 누르면 PC 소리를 자막으로 바꾸고, 자막에서 퀴즈·사연·선물 안내를 찾아
  고릴라 공감로그로 **퀴즈 정답과 사연을 자동으로 보냅니다**. 수집 중인지는 첫 화면과 항상 위에 뜨는 자막 창에서 바로 보입니다.
- **게시판 사연**: 본인의 실제 경험을 재료로 원고를 만들고, 검사·승인을 거쳐 게시판 글쓰기 화면에 **입력만** 합니다 (등록 버튼은 직접).
  방송 중 진행자가 **게시판에 사연을 남겨 달라**고 하면, 검사 경고가 없는 원고는 **승인 없이 입력하고 등록까지** 누릅니다 (0.29, SBS 로그인은 처음 한 번 직접).

채널: SBS 파워FM·러브FM·고릴라M, MBC FM4U, KBS 쿨FM·해피FM·1라디오가 기본으로 들어 있고, 첫 화면 **채널 추가**로 늘릴 수 있습니다.
보내는 방법은 청취 화면에서 고릅니다: **앱 채팅**(SBS 고릴라·MBC mini·KBS 콩, 무료) 또는 **휴대폰 문자**(안드로이드 USB 연결, 건당 약 50원).

메뉴: **청취**(첫 화면) · **퀴즈 기록** · **사연** · **선물 기록** · **코너** · **프로그램** · **인물** · **내 정보** · **설정**

명세: [`docs/radio_participation_plan_20261002.md`](docs/radio_participation_plan_20261002.md)

## 사연: 하는 것 / 하지 않는 것

사연은 명세 4절의 검증 순서 중 **1~3단계**까지만 구현했습니다.

| 단계 | 내용 | 상태 |
|---|---|---|
| 1) 읽기 전용 점검 | 사용자가 직접 로그인한 글쓰기 화면에서 입력 요소·글자 제한 안내·CAPTCHA 흔적을 읽어 보고서로 남김 | 구현 (아무것도 입력·클릭하지 않음) |
| 2) 로컬 모의 화면 테스트 | 이 PC 안의 가짜 글쓰기 화면에 입력하고 모의 '등록'까지 시험 | 구현 |
| 3) 실제 화면 입력 | 승인된 원고를 실제 글쓰기 화면에 채워 넣기만 함 | 구현 — **등록 버튼은 사용자가 직접 누름** |
| 4) 실제 1건 제출 | 사용자가 직접 등록 버튼을 누르고 결과를 제출 이력에 기록 | 사용자 수동 |
| 5) 자동 실행 | 방송에서 게시판 사연을 받을 때, 검사 경고 0건인 원고만 입력·등록까지 | 구현 (0.29) — 청취 화면 *게시판 사연도 자동 등록* 으로 끔 |

하지 않는 것:
- 원고 화면의 '실제 화면에 입력하기'는 등록·임시저장 버튼을 누르지 않음 (그 경로에는 클릭 코드 자체가 없음 — 테스트로 확인).
  등록까지 누르는 것은 아래 **게시판 자동 등록** 하나뿐입니다.
- 로그인·CAPTCHA·추가 인증 처리 또는 우회
- 비밀번호·쿠키·세션 토큰을 채팅·GitHub·기록 파일에 저장 (게시판 자동 등록의 로그인은 데이터 폴더 `browser_profile` 안에
  브라우저가 평소처럼 보관합니다. 지우면 로그아웃)
- 사연 원고에 유료 AI API 연결 (원고 다듬기는 쓰던 대화형 AI에 요청문을 붙여 넣는 방식)
- 다른 청취자 사연 수집

## 설치·실행 (Windows)

1. Python **3.12 또는 3.11** 이 필요합니다 (3.13·3.14 도 됨). 가장 새 Python(3.15)에는 음성 인식 부품(faster-whisper 가 쓰는
   ctranslate2·onnxruntime)이 아직 없어 퀴즈 자동이 설치되지 않습니다. 2번의 `start_windows.bat` 이 알아서 맞춥니다 (0.42):
   - `find_python.py` 가 후보(py 3.12·3.11…, 설치 폴더, 등록부)를 **실제로 실행해 버전을 확인**하고 고릅니다
     (새 Python 설치 관리자 `py` 는 3.12 가 없는데도 '성공'을 돌려줄 때가 있어 종료 코드를 믿지 않음 — 0.41 까지 이 때문에 3.15 로 다시 켜졌음).
   - 없으면 **Python 3.12 를 자동 설치**: ① `py install 3.12` (묻는 것이 있으면 Y) ② winget ③ python.org 설치 파일(조용히, 내 계정에만).
   - 이미 3.15 로 만든 `.venv` 는 3.12 로 다시 만듭니다. 그래도 안 되면 python.org 내려받기 화면을 열고 멈추니,
     ["Looking for a specific release?"](https://www.python.org/downloads/) 에서 3.12 를 골라 설치한 뒤 다시 실행하세요.
   ("Python was not found … Microsoft Store" 는 윈도우의 가짜 바로 가기가 띄우는 안내라 무시해도 됩니다.)
   - 패키지는 관리 화면(Flask)과 퀴즈 자동을 따로 설치합니다. 퀴즈 부품 하나가 실패해도 관리 화면은 켜지고,
     관리 화면 패키지가 없으면 끝없이 다시 켜지 않고 안내하고 멈춥니다.
   - **음성 인식 부품이 없을 때 스스로 고침**: 듣기를 켜 두었는데 faster-whisper 가 없으면 관리 화면이
     Python 이 맞으면 뒤에서 설치하고(6시간에 한 번), 너무 새 Python 이면 하루 한 번 Python 3.12 로 다시 설치하고 다시 켭니다
     (5~10분, 듣던 방송은 이어서). 첫 화면에 안내와 **지금 고치기** 버튼이 나옵니다.
2. 이 폴더의 **`start_windows.bat`** 을 더블클릭합니다.
   - 처음 한 번은 필요한 패키지(음성 인식 포함)를 설치하느라 몇 분 걸립니다.
   - 브라우저에 관리 화면(`http://127.0.0.1:5000`)이 열립니다. 이 PC에서만 접속됩니다 (밖에서는 https://radio.haetsallab.com).
3. 끝낼 때는 검은 창에서 `Ctrl + C` 를 누르거나 창을 닫습니다.
4. **업데이트**: 새 압축 파일은 기존 폴더에 덮어써도, 새 폴더에 풀어도 됩니다. 경험·사연·설정은 프로그램 폴더 밖
   (`C:\Users\<이름>\AppData\Local\RadioHelper`)에 저장되어 그대로 남습니다. 예전 버전 폴더(`data/`)에 있던 데이터는
   처음 실행할 때 프로그램 폴더 → 같은 곳에 풀어 둔 다른 업데이트 폴더 → 내려받기·바탕 화면·문서 순으로 찾아, 가장 최근에 쓴 것을 한 번 옮겨 옵니다.

**관리 화면이 안 뜰 때**
- 검은 창의 `[점검]` 줄을 보세요. 서버가 뜬 것을 확인한 뒤 브라우저를 열고, 첫 화면이 실제로 열리는지 스스로 확인해 결과를 적습니다.
- 5000번을 예전에 켠 검은 창이나 다른 프로그램이 쓰고 있으면 `[알림]` 을 띄우고 5001, 5002… 다음 번호로 엽니다. 이때 주소는 검은 창의 **관리 화면:** 줄에 나온 주소입니다.
- 예전 검은 창은 예전 파일로 돌고 있을 수 있으니 닫으세요. 작업 표시줄에 검은 창이 여러 개면 하나만 남기세요.
- `[점검]` 이 실패라고 나오면 검은 창 전체를 캡처해 보내 주세요.

글쓰기 화면 입력에는 Windows에 기본 설치된 **Microsoft Edge**를 씁니다. 별도 브라우저 다운로드가 필요 없습니다.
(Edge 대신 Chrome을 쓰려면 환경 변수 `RADIO_HELPER_BROWSER_CHANNEL=chrome`)

macOS·Linux: `python3 -m venv .venv && .venv/bin/pip install -r requirements.txt && .venv/bin/python -m playwright install chromium && .venv/bin/python -m radio_helper`

## 사용 순서

1. **기본 정보** — 방송용 이름, 공개 가능한 지역·직업 표현, 가족 호칭, 문체, *본문에 나오면 안 되는 단어*(실명·회사명 등)를 정합니다.
2. **실제 경험** — 경험 1건마다 언제·누가·무슨 일·기억나는 말(정확한 인용인지 취지인지)·포인트·결말을 편하게 적고 *"실제로 있었던 일"* 을 체크합니다. 처음엔 3건이면 충분합니다.
3. **코너** — 공식 게시판 공지를 **직접 읽고** 모집 여부·마감·글자 제한·AI 보조 작성 제한 여부를 적은 뒤 *"공지 확인 완료"* 를 누릅니다. 공지 원문을 붙여 두면 다음에 공지가 바뀌었을 때 재검토 전까지 제출이 멈춥니다.
4. **원고 만들기** — 경험 화면에서 코너를 고르고 *원고 만들기* 를 누르면 템플릿 초안이 생깁니다(적은 문장을 그대로 배치하고 인사·맺음말만 붙임).
   더 매끄럽게 하려면 원고 화면의 **요청문 복사** → 쓰던 대화형 AI에 붙여넣기 → 받은 결과를 **결과 붙여넣기** 칸에 넣습니다.
5. **검사·승인** — 자동 검사(연락처·주소·금지어·재료에 없는 민감 소재·숫자·직접 인용·글자 수·이전 글과의 유사도)를 확인하고, 사건·인물·결과가 실제와 같다는 확인란을 체크해 승인합니다. 내용을 고치면 승인이 풀립니다.
6. **모의 화면 입력 시험** — 먼저 가짜 글쓰기 화면으로 흐름을 확인합니다.
7. **실제 화면 입력** — 코너 화면에서 *점검용 브라우저 열기* 로 글쓰기 화면의 입력 요소를 한 번 확인하고, 제목·본문 입력 요소를 코너 설정에 적어 둡니다.
   SBS 글쓰기 화면은 코너마다 틀이 같아서, 한 코너에서 적어 두면 입력 요소가 빈 다른 SBS 코너도 그것을 씁니다(제출 조건에 '어느 코너 것을 쓰는지' 표시). 그다음 원고 화면에서 *실제 화면에 입력하기* → 열린 브라우저에서 직접 로그인 → 도구가 내용을 채움 → **내용 확인 후 등록 버튼은 직접 클릭**.
8. **제출 이력** — 게시판에서 글이 올라간 것을 확인하면 상태를 *등록 확인* 으로 바꾸고 글 주소를 남깁니다. 사연 채택·당첨·상품 수령은 각각 따로 기록합니다.

## 프로그램 목록 (전 채널)

**프로그램** 화면에 채널별로 정리됩니다. 처음에는 파워FM 13개(01시 애프터클럽 ~ 23시 딘딘의 뮤직하이)와 러브FM 일부(이숙영의 러브FM)가 들어 있습니다.
처음 목록은 2026-10-02 웹 검색 결과로 확인한 것이라, **공식 페이지에서 새로고침**으로 이 PC에서 다시 확인하세요.

- 각 프로그램 공식 페이지에서 방송 시간·요일을 다시 읽고, 코너·게시판 링크를 **코너** 목록에 추가합니다(모집 여부는 '미확인').
- **코너** 화면의 **코너·게시판 모두 수집** 도 같은 작업입니다(3~5분). 코너 게시판(`…/cornerboards/번호`)은 그 페이지를 한 번 더 열어 코너 탭(`?cornerid=`)을 모두 모읍니다. 프로그램마다 최대 4곳까지 더 열어 봅니다.
  - 메뉴 링크뿐 아니라 페이지 글·받아 온 데이터에 적힌 게시판 주소도 모읍니다. 글 하나 주소(`?board_no=`)는 게시판 주소로 줄이고, 글 제목은 이름으로 쓰지 않습니다.
  - 이름을 못 읽은 게시판은 `(이름 확인 필요) 게시판 번호` 로 넣습니다. 코너 화면에서 열어 보고 **코너 이름** 을 고치세요.
  - 프로그램별로 찾은 개수가 칩으로 보이고, 노란색 0 은 아직 못 찾은 프로그램입니다. 실행 기록(`data/logs/programs_*.log`)에 프로그램마다 찾은 개수·읽은 링크 수가 남습니다.
  - 공식 페이지가 다른 주소로 넘어가면(프로그램 주소 변경) 넘어간 주소의 게시판도 그 프로그램 것으로 봅니다. 새로 편성에 넣은 프로그램의 게시판도 같이 모읍니다.
  - MBC·KBS 게시판은 다른 사이트라 모으지 않습니다(SBS만).
  - 코너 게시판은 글쓰기 화면 주소(`…/cornerboardwrite/번호/?cornerid=`)를 자동으로 채웁니다(처음 넣어 둔 '사연과 신청곡'과 같은 모양). 일반 게시판(`/boards/`)은 모양을 몰라 비워 둡니다.
- SBS 라디오 첫 화면에서 목록에 없는 프로그램을 찾으면 그 페이지에서 **채널·방송 시간**을 읽어 편성에 넣습니다. 둘 중 하나라도 못 읽으면 '후보'로 남깁니다.
- 편성에 없는 시간에 청취해도 '러브FM 방송'처럼 채널 이름으로 기록하며 퀴즈·사연은 그대로 동작합니다.
- 페이지를 읽기만 하고 로그인·입력은 하지 않습니다. 시간을 읽지 못한 프로그램은 기존 값을 그대로 둡니다.

## 청취 시작 (원스텝)

라디오(고릴라)를 켜고 관리 화면 첫 화면 **청취**에서 듣는 채널을 고른 뒤 **▶ 청취 시작**을 누릅니다. 멈출 때는 **■ 청취 중지**.

- **켤 때마다 "뭐로 들으시겠어요?"** (0.35): `start_windows.bat` 으로 켜면 지난번 채널로 저절로 시작하지 않고, 첫 화면 맨 위에서
  방송국 앱별(SBS 고릴라 · MBC mini · KBS 콩)로 채널을 고르게 합니다. 누르면 바로 그 채널로 청취를 시작하고(선택 항목은 지난번 그대로),
  정답·사연은 그 방송의 채팅 앱으로 보내며 그 앱만 다시 띄웁니다 — MBC를 들을 때 고릴라를 켜지 않습니다.
  고르기 전에는 듣지도 보내지도 않습니다. *지금은 듣지 않음* 도 있습니다.
- **오류로 꺼졌다가 저절로 다시 켜질 때는 묻지 않습니다**: 관리 화면이 비정상으로 꺼져 `start_windows.bat` 이 다시 켤 때와
  듣기 실행기가 꺼져 관리 화면이 다시 띄울 때는 고른 채널로 그대로 이어 갑니다 (재시작 루틴은 예전과 같음).

- **눈으로 확인**: 첫 화면에 ● 수집 중(빨간 점 깜빡임)·소리 크기 막대·실시간 자막이 2초마다 갱신되고, 화면 오른쪽 아래에
  항상 위에 뜨는 작은 **자막 창**이 열립니다(닫아도 청취는 계속). 메뉴의 '청취' 옆 빨간 점은 청취 중이라는 뜻입니다.
- 상태 글: *시작하는 중* → *음성 인식 준비 중*(처음 한 번은 그래픽카드 점검과 모델 내려받기 약 1.6~3GB로 몇 분) → *수집 중*. 오류가 나면 그 내용이 상태 글과
  '최근 감지·전송'에 그대로 보이고 30초 뒤 다시 시도합니다.
- **마지막 녹음** 줄이 10초마다 바뀝니다(소리 크기·받아쓰기 시간·받아쓴 말, 말소리가 없으면 '말소리 없음'). 자막 칸에는 키워드와 상관없이 받아쓴 말이 전부 나옵니다.
- 실행기 신호가 끊기면 **응답 없음**(보라색)으로 바뀌고, 실행기 기록 파일 끝부분이 화면에 나옵니다. **↻ 다시 시작**으로 다시 띄웁니다.
  관리 화면을 다시 켜면 청취가 켜져 있던 경우 자동으로 이어서 듣습니다.
- **음성 인식 정확도** (고릴라·인식 설정, 기본은 모두 자동)
  - **장치 auto**: NVIDIA 그래픽카드가 있으면 `start_windows.bat` 이 그래픽카드 라이브러리(약 1GB, `requirements-gpu.txt`)를 함께 설치하고,
    실행기가 별도 프로세스로 그래픽카드를 한 번 점검한 뒤 되면 그래픽카드로 돌립니다. 점검에 실패하면 CPU로 돌리며(라이브러리 문제로 실행기가 꺼지는 일 방지),
    점검 결과는 저장해 두었다가 라이브러리가 바뀌거나 실패한 지 하루가 지나면 다시 점검합니다.
  - **모델 auto**: 그래픽카드면 `large-v3`, CPU면 `large-v3-turbo`(논리 코어 16개 미만이면 `small`)를 씁니다.
    예전 기본값(small·CPU)을 쓰던 PC는 업데이트 후 처음 켤 때 한 번만 자동으로 바뀝니다. 직접 고른 다른 값은 그대로 둡니다.
  - **겹쳐 듣기**: 10초 조각 끝 3초 안에서 시작한 말은 확정하지 않고 다음 조각과 이어서 다시 받아씁니다.
    조각 경계에서 말이 깨지거나 빠지는 일을 막는 대신, 그 말은 10초 늦게 자막에 나옵니다 (설정 '겹쳐 듣기' 0이면 끔).
  - **받아쓰기 후보 수**(기본 5): 여러 후보를 비교해 고릅니다. 받아쓰기가 녹음보다 느리다는 안내가 뜨면 1로 줄이세요.
  - **단어 힌트**: 퀴즈·초성 자음 이름(기역·니은…)·기프티콘 같은 방송 낱말과, 듣는 프로그램의 진행자·코너 이름을
    모델에 미리 알려 줍니다. 자주 틀리는 이름은 *음성 인식 단어 힌트* 칸에 쉼표로 적어 두세요.

### 인물 관계도 · 사연 보관함 (메뉴 '인물')
- **가져오기**에 인물 관계도 파일(`character-map.md`)을 넣으면 인물 카드와 실제 사건(연표)이 **인물**에 들어갑니다.
  가운데 '나'를 중심으로 묶음(우리 집·본가·처가·외가·직장·친구…)별로 그린 **관계도**와 **인물 목록**으로 봅니다.
- 인물마다 사연에 쓰는 **호칭**(예: 와이프, 대학 친구, 회사 동료)을 정합니다. 사연과 AI 요청에는 실명 대신 호칭만 쓰고,
  실명(앞 낱말)이 사연에 나오면 자동으로 막습니다.
- **화자는 언제나 '나'**입니다. 실제 경험에서 '누구 이야기인가요?'를 고르면 "제 와이프 이야기인데요"처럼 관계로 시작해 씁니다.
  인물 화면의 실제 사건에서 바로 경험을 만들 수 있습니다 ('실제로 있었던 일' 확인 후 사연에 씀).
- **실제 사건 → 경험으로 모두 옮기기**: 인물 화면 위쪽 버튼(또는 인물마다 버튼)으로 관계도 연표의 실제 사건(대화·통화로 확인한 것)을
  한 번에 **'실제로 있었던 일'로 확인된 경험**으로 만듭니다. 관계도 연표는 사용자가 확인한 실제 사건이라 따로 검수하지 않고 바로 사연 재료로 씁니다.
  가상(〔사연〕)·임의 사건은 옮기지 않고, 이미 옮긴 사건은 다시 만들지 않습니다.
- **사연처럼 풀어 쓰기**: 옮기면 곧바로 뒤에서 Claude API로 사건 한 줄을 사연처럼 풀어 씁니다(8건씩, 136건이면 몇 분, 수천 원 수준).
  사실(사건 한 줄)은 바꾸지 않고 '바꾸면 안 되는 사실'로 남기며, 그 인물의 확인된 정보(나이·직업·성격 등, 〔임의〕 정보 제외)와
  나의 마음·배경·마무리로만 살을 붙입니다. 새 사건·장소·숫자·대사는 만들지 않고, AI가 재료에 없는 내용을 넣었다고 표시하거나
  실명·연락처가 들어가면 원래 한 줄을 그대로 둡니다. 진행 상황은 **내 정보 → 실제 경험** 위쪽에 보입니다
  (진행 중이면 20초마다 새로 고침, 실행기가 꺼졌으면 '멈춤'과 실행 기록 끝부분·다시 시작 버튼, 끝나면 결과 수).
- 사연 로그(`.jsonl`)는 **사연 보관함**에 들어갑니다. 원본 사연을 각색한 **가상 사연은 그대로는 보내지 않고** AI 사연 초안의 재료로도 쓰지 않습니다.
  인물에게 실제로 비슷한 일이 있었다면 사연을 열어 **실제 있었던 일로 옮기기**를 누릅니다. '확인 전' 경험으로 복사되며(인물·시기·신청곡 포함),
  실제와 다르게 적힌 부분을 고치고 *"실제로 있었던 일"* 을 체크해야 사연으로 보냅니다.
  보관함 위쪽의 **경험으로 모두 가져오기 (확인 전)** 로 한 번에 가져올 수도 있습니다. 이때도 모두 '확인 전'이라 보내지 않고,
  하나씩 열어 고치고 체크한 것만 보냅니다.
  **사연 목록 파일로 받기** (0.34, 내 정보 → 실제 경험 위쪽): 확인한 사연을 인물별로 묶은 **읽기용(.txt)** (인물은 실명 대신 호칭,
  *확인 전 것도 함께* 를 누르면 확인 전 것까지)과 **사연 jsonl로 받기 (전체)** (0.39 — 보관함 화면에도 있음)로 받습니다.
  jsonl 에는 확인한 사연·확인 전 사연·아직 옮기지 않은 보관함 사연(가상·실제 구분, 원본 출처)이 모두 들어가고, 정확히 되붙이도록
  인물 이름도 적힙니다. 다른 PC나 *사연 전체 초기화* 뒤에 *가져오기*에 넣으면 보관함이 돌아오고, **확인해 둔 사연은 확인된 실제
  경험으로 바로 되살아납니다**(고친 글·공감로그 한 줄·마무리·인물 그대로, 다시 확인할 필요 없음). 확인 전이던 것은 보관함으로 돌아옵니다.
  파일은 이 PC에서 바로 내려받으며 어디로도 보내지 않습니다 (가족 이름이 들어 있으니 공유에 주의).
  **10개씩 보고 확인하기**(보관함·실제 경험 화면의 버튼): 확인 전 사연을 한 화면에 10개씩 펼쳐 이름·시기·본문을 바로 고치고,
  맞는 것에 '실제로 있었던 일 맞음'을 체크한 뒤 **다음 10개**로 넘어갑니다. 체크하지 않은 것은 확인 전으로 남고 처음부터 다시 볼 수 있습니다.
  아닌 것은 **아님 · 지우기**를 체크하면 지웁니다(보관함 원본도 함께 지워 다시 가져오지 않음).
- **사연 전체 초기화** (0.37, 실제 경험 화면 맨 아래 · 보관함 화면의 링크): 사연 보관함과 실제 경험(고치고 승인한 사연)·원고를
  모두 지웁니다. 확인 칸에 '초기화'라고 적어야 지우고, 지우기 전에 데이터 파일 전체를 데이터 폴더 `backups\before_story_reset_…`
  에 자동으로 백업합니다(되살릴 때는 도우미를 끄고 그 파일을 `radio_helper.sqlite3` 로 바꿔 넣음). 인물 관계도·내 정보·고릴라 위치·
  채널·코너·설정은 그대로입니다. 보낸 사연·게시판 제출 기록은 기본으로 남기고(같은 방송국 재전송 막기), 체크하면 그 기록과 증거 사진도 지웁니다.
- **지우기** (0.31): 보관함 사연 화면의 *보관함에서 지우기*(옮겨 둔 확인 전 경험도 함께, 이미 확인한 경험은 남김),
  경험 화면의 *이 경험 지우기*(확인 전·원고 없는 것만), 10개씩 보기의 *아님 · 지우기*.
- **사연 모음 + 인물 줄** (0.31): 사연 로그(`.jsonl`)에 `{"type": "person", "name", "job", "job_tag", "alias", …}` 줄이 있으면
  그 인물(친구 등)을 먼저 추가하거나 직업을 적은 뒤 사연을 붙입니다. 이미 있는 인물은 이름·호칭·이름 끝(김○○ ← ○○, 한 명일 때만)으로 찾고,
  사용자가 바꾼 호칭·가까움은 그대로 둡니다. 직업이 〔주신〕이면 바꾸고, 〔임의〕(사연 묶음용으로 정한 값)이면 비어 있을 때만 채웁니다.
  인물 줄로는 실제 사건을 넣지 않습니다 — 사연은 모두 보관함의 가상(각색) 사연이라 확인 전에는 보내지 않습니다.
- 인물·사연 정보는 이 PC의 데이터 폴더에만 저장됩니다 (GitHub에 올리지 않음).

### 키워드 · 채팅창 교차 분석
- 키워드: **퀴즈·정답·오답·힌트**(퀴즈) / **사연·신청곡·게시판**(사연) / **선물**(선물). 자막에서 색으로 강조됩니다.
- 키워드가 들리면 그때부터 **채팅창에 올라오는 글도 10초마다 찍어** 모으고(설정 → 앱 채팅 → ④ 채팅창 영역 지정),
  분석할 때 녹취와 함께 Claude에 보내 교차 확인합니다. 받아쓰기가 틀린 낱말·문제·힌트·오늘의 주제를 채팅 글로 바로잡습니다.
  사진은 분석 한 번에 첫 장 + 최근 2장(장당 수백 토큰)만 보내고 저장하지 않습니다(마지막 한 장만 확인용으로 이 PC에 남김).
  다른 창에 가려져 있어도 앱 창만 따로 찍습니다 (최소화하면 못 찍음). 영역을 지정하지 않으면 녹취만으로 분석합니다.
- 힌트가 나오면 같은 문제로 묶어 다시 분석하고, 답이 더 확실해졌으면 아직 안 보낸 문제를 새 답으로 보냅니다.

### 기발한 오답
- 라디오 퀴즈는 정답만 뽑히지 않으므로, 분석할 때 **웃긴 포인트가 있는 오답**을 함께 만듭니다. 웃긴 포인트가 없거나 기발함 점수가 낮으면(기본 0.7 미만) 쓰지 않습니다.
- 보낼 답 고르기: 진행자가 재밌는 오답을 환영하거나 정답이 불확실하면 기발한 오답, 정답이 확실하면 기본 30%만 기발한 오답(설정 '기발한 오답 비율').
- 개인 사연을 지어내지 않고, 비하·정치·선정적인 농담은 쓰지 않습니다. 청취 화면 **기발한 오답 섞기**로 끌 수 있습니다.

### 사연: 채팅창 / 게시판
- 기본은 채팅창(앱 채팅 또는 문자)입니다. 진행자가 **'게시판에만'** 받는다고 하면 채팅으로 보내지 않고, 그 프로그램 게시판용 원고(제목·본문)를
  **원고 검토함**에 만듭니다. 진행자가 게시판(코너) 이름을 말하면 그 게시판을, 아니면 '사연'이 들어간 게시판을 고릅니다.

#### 게시판 자동 등록 (0.29, 청취 화면 *게시판 사연도 자동 등록* — 기본 켬)
- 원고 검사에 **경고·차단이 하나도 없으면** 사람 승인 없이 원고를 자동 승인하고, 등록 도구가 글쓰기 화면에 입력한 뒤 **등록까지** 누릅니다
  ('등록하시겠습니까?' 확인 창도 확인). 등록 뒤 게시판에서 제목이 보이면 *등록 확인*, 안 보이면 *결과 불명*(게시판에서 확인)으로 남습니다.
- 창 없이 돌고, **SBS 로그인이 필요하면 브라우저 창이 뜹니다 → 직접 로그인**하면 이어서 등록합니다 (10분 대기).
  로그인은 도우미 전용 브라우저 프로필에 남아 **다음부터는 창 없이** 등록합니다. 처음 한 번은 청취 전에 미리 해 두면 좋습니다.
- **보안 문자(CAPTCHA)** 가 보이면 창을 띄우고 기다립니다. 직접 풀고 **등록은 직접** 누르세요 (우회하지 않음).
- 입력 요소를 모르면 글쓰기 화면에서 제목·본문 칸을 찾아 코너에 적어 둡니다. 등록 버튼은 '등록'·'확인' 글자로 찾고,
  못 찾으면 코너 화면 **글쓰기 화면 입력 설정 → 등록 버튼** 칸에 적습니다.
- 자동으로 **올리지 않는 경우**(원고 검토함에 남고 사연 목록에 이유가 적힘): 검사 경고(재료에 없는 숫자·직접 인용·비슷한 글 등),
  실제 경험으로 확인하지 않은 재료, 코너 마감 지남·'모집 마감' 표시·AI 보조 작성 제한, 글쓰기 주소 없음, 같은 경험을 SBS에 이미 보냄,
  일괄 중지. 로그인 대기 시간이 지나도 원고 검토함으로 돌아옵니다. 하루 등록 수 상한은 없습니다(무제한, 0.30).
- 증거 사진 2장(입력 완료·등록 뒤 화면)이 제출 이력에 붙고, **보낸 사연 목록**에 '게시판'으로 나옵니다.
- **신청곡은 알아서 고릅니다** (0.34, 청취 화면 *신청곡 알아서 고르기* — 기본 켬): 진행자가 신청곡도 받거나 신청곡을 곁들이는 코너면,
  경험·내 정보에 적어 둔 곡이 주제에 맞으면 그것을, 아니면 오늘 주제·사연 분위기·프로그램·시간대·계절에 맞는 실제 곡을 골라
  '가수 - 제목'으로 승인 없이 함께 보냅니다. 노래에 얽힌 추억·사건은 지어내지 않고 곡만 신청합니다.
  곡 이름은 사건이 아니므로 '재료에 없는 숫자' 같은 검사에서 뺍니다. 끄면 예전처럼 적어 둔 곡만 씁니다.

### 채널과 보내는 방법
- **앱 채팅**: 채널에 맞는 앱으로 보냅니다 (SBS → 고릴라, MBC → mini, KBS → 콩). **설정 → 앱 채팅·인식 설정 → 원버튼 찾기**
  한 번이면 됩니다 (어긋날 때만 입력칸·전송 버튼을 네모로 직접 지정). 그다음 전송 테스트로 확인하세요.
- **원버튼 찾기** (0.50): 앱이 켜져 있는지 → 입력칸·전송 버튼·채팅 목록 자리를 한 번에 찾아 모니터 기준으로 저장하고, 네모를 그린
  확인 사진(파랑 입력칸 · 초록 전송 · 보라 채팅 목록)을 보여 줍니다. *모든 앱 찾기*는 켜져 있는 앱(고릴라·콩·mini·레인보우)을 차례로 찾습니다. 글은 보내지 않습니다.
  - 찾는 순서: 화면 요소(UIA) → **Claude 가 앱 창 사진을 보고**(Claude 연결이 있을 때, 한 번 부름) → 보내 준 세 앱 화면에서 잰
    **알려진 배치**. 알려진 배치로 찾은 것은 앱 화면이 다르면 어긋날 수 있으니 확인 사진을 꼭 보세요.
  - **채팅이 닫혀 있으면**(고릴라 공감로그 대신 광고 띠만 보일 때 등) 말풍선 버튼을 한 번 눌러 열고 다시 찾습니다. 그 자리가 다른
    프로그램에 가려 있으면 누르지 않고 알려 줍니다.
  - 로그인 안내('공감로그를 남기시려면 로그인', '로그인 후 채팅에 참여')가 보이면 알려 줍니다. 로그인은 앱에서 직접 하세요.
  - **듣는 중에 채팅 창을 못 찾으면** 5분에 한 번 저절로 다시 찾습니다 (Claude 는 부르지 않고, 창을 찍지 않음). 환경 점검도
    '앱이 꺼짐'과 '켜져 있지만 채팅 자리를 못 찾음'을 나눠 알려 줍니다 (예전에는 켜져 있어도 '실행하세요'라고 나왔음).
- **휴대폰 문자**: PC에 USB로 연결한 안드로이드 휴대폰의 기본 문자 앱으로 보냅니다. 받는 번호가 작성 화면에 '#'까지 그대로 보일 때만 전송 버튼을 누릅니다.
  끝에 방송용 이름(내 정보)을 붙입니다. 준비 방법은 **설정 → 휴대폰 문자 설정**에 있습니다 (USB 디버깅, Google platform-tools).
  기본 번호: 파워FM #1077 · 러브FM #1035 · MBC FM4U #8000 · KBS 쿨FM #8910 · KBS 해피FM #1061 (KBS 1라디오 등 모르는 번호는 직접 입력).
- 확인 대기 글은 **앱 채팅으로 보내기 / 문자로 보내기** 중 골라 보낼 수 있습니다. 진행자가 '문자로만 받는다'고 하면 앱 채팅 자동 전송은 멈추고 확인 대기에 남습니다.
- 앱 채팅은 '창을 못 찾았다'는 판단으로 보류하지 않고 **일단 보냅니다**. 창이 정말 없거나 가려져 누르기 전에 막히면(보내지 않은 것)
  1분마다 다시 시도하고, 20분이 지나면 늦어서 확인 대기로 남깁니다. 휴대폰 문자는 연결되면 보냅니다.
  고릴라가 켜져 있는지는 보낼 때와 같이 ①②로 표시한 자리의 창으로 봅니다.
- **채팅 창은 옮기지 않습니다** (0.52): 예전에는 옮겨진 채팅 창을 위치를 지정할 때 자리로 되돌려(강제 롤백) 보냈습니다.
  이제 채팅 창은 사용자가 둔 자리·크기 그대로 두고, **누를 자리를 창을 따라 옮겨** 누릅니다 (지정할 때와 크기가 거의 같은
  그 앱의 창만 — 플레이어 창을 누르지 않게). 크기가 많이 달라졌으면 누르지 않습니다(원버튼 찾기로 다시 찾음).
- **채팅 창이 안 보이면 되살려서 보냅니다** (0.32): 최소화·트레이로 숨은 창은 그 자리에 다시 띄우기만 합니다. 앱이 아예 꺼져 있으면 실행 파일(위치를 지정할 때 저장 — 0.32 이전에
  지정했다면 한 번 다시 지정하면 저장됨) 또는 시작 메뉴 바로 가기로 다시 켜고 창이 뜨기를 40초까지 기다립니다.
  한 일은 퀴즈 기록·최근 감지에 *고릴라 채팅 창이 그 자리에 없어 최소화돼 있어 되살림 → …* 처럼 남습니다.
  그래도 그 자리에 앱 창이 없을 때만(로그인 화면 등) 보내지 않습니다 — 바탕화면에 Enter 를 누르면 아이콘이 실행될 수 있어서입니다.

### 받아쓰기 테스트
첫 화면의 **🎤 받아쓰기 테스트 (10초)** 는 녹음 장치 → 10초 녹음(소리 크기) → 음성 인식 모델 → 받아쓰기를 차례로 해 보고 단계별 결과를 보여 줍니다.
- 처음 한 번은 그래픽카드 점검과 모델 내려받기(1.6~3GB)로 몇 분 걸리며, 준비 상태에 지금 단계가 나옵니다.
- 테스트 프로그램이 도중에 꺼지면 '진행 중'에 머물지 않고 '도중에 멈춤'으로 바뀌어 다시 할 수 있습니다.
- 청취 중에 실제로 받아쓴 말이 있으면(최근 7일) 테스트를 따로 하지 않아도 준비 상태가 OK 입니다.
진행자가 말할 때 눌러 보세요. 도중에 프로그램이 꺼지면 어느 단계에서 멈췄는지 남습니다.
- 고릴라 창을 찾지 못해도 **듣기·자막은 계속**합니다. 보낼 정답·사연은 1분마다 고릴라 창을 다시 찾아, 찾으면 보냅니다(20분 넘게 지난 것은 늦어서 보내지 않음).
- 선택 항목: *퀴즈 정답 자동 전송* · *사연 자동 전송*(검사 경고가 없는 글만) · *선물 정보 기록* · *자막 창 띄우기*.
- 이전 버전은 **예약 시간에만** 들었기 때문에 예약이 없으면 음성 인식이 전혀 돌지 않았습니다. 예약은 이제 선택(설정 화면)입니다.

### 퀴즈
1. 스피커로 나가는 소리를 10초 단위로 녹음하고(마이크 아님), 이 PC에서 무료 음성 인식(faster-whisper)으로 글자로 바꿉니다. **오디오는 저장하지 않습니다.**
   - 귀로 들리는 소리가 아니라 윈도우가 스피커로 **보내는 신호**를 받습니다. 그래서 **스피커 음소거(작업 표시줄 스피커 아이콘)** 를 해도 받아쓸 수 있습니다.
   - 반대로 **고릴라 앱 안 볼륨**이나 윈도우 '볼륨 믹서'의 **고릴라 볼륨**을 0으로 하거나 고릴라를 멈추면 신호 자체가 없어 받아쓸 수 없습니다. 둘은 최대로 두세요.
   - 윈도우 전체 볼륨 막대를 낮췄을 때 녹음 크기가 줄어드는지는 PC(소리 장치)마다 다릅니다. **받아쓰기 테스트**의 '소리 크기'로 확인하세요. 작게 들어오면 받아쓰기 전에 자동으로 최대 100배까지 키웁니다.
   - 소리를 듣기 싫으면 볼륨을 내리지 말고 **음소거**를 쓰는 것이 가장 확실합니다.
2. '퀴즈·정답·초성·문제 나갑니다' 같은 말이 들리면 40초 더 듣고, 최근 3분 자막을 **Claude API**로 보내 문제·정답·응모 방법을 정리합니다.
3. 아래 조건을 **모두** 만족하면 고릴라 공감로그 입력칸에 정답을 넣고 전송합니다. 못 채우면 **퀴즈 기록 → 확인 대기**에 남기고, **이 답으로 보내기**를 누르면 보냅니다.
   - *퀴즈 정답 자동 전송* 을 켰음, 정답 확신도가 기준(기본 0.8, 설정에서 변경) 이상
     - 단, *퀴즈는 무조건 보내기*(기본 켜짐)면 **객관식·주관식 모두** 정답 후보가 있으면 확신도가 기준보다 낮아도 가장 그럴듯한 답을
       보냅니다 (틀려도 손해가 없으므로). 이때는 확신이 낮다고 기발한 오답으로 바꾸지도 않습니다. 청취 화면에서 끌 수 있습니다.
       정답 후보가 아예 없을 때만 확인 대기에 남습니다. 0.32부터는 문제가 일부만 들려도 힌트·보기·채팅창으로 가장 그럴듯한 답을
       반드시 하나 만들고(확신도는 낮게), 삼행시·이행시 같은 창작 응모도 지은 답을 정답 칸에 넣어 보냅니다.
   - 진행자가 '문자로만'처럼 고릴라가 아닌 방법을 말하지 않음 (청취 모드는 모든 채널의 고릴라 응모를 열어 둠)
   - 최근 1시간 전송이 상한(기본 4건) 미만, 일괄 중지 꺼짐
4. 같은 문제를 다시 안내하면 한 건으로 묶고, 정답 발표는 새 문제로 보지 않습니다. **한 번 보냈거나 보냈는지 모르는 문제는 다시 보내지 않습니다.**
5. 정답 인정·당첨·상품 수령은 **퀴즈 기록**의 표에서 바로 기록합니다.
6. 퀴즈를 풀면 첫 화면 상태 줄 아래와 자막 창에 **노란 줄**(퀴즈 시각 · 문제 → 보낸 답 · 상태)이 30분 동안 보입니다.
   상태 이름: *채팅에 올라감 확인*(앱 채팅 목록에서 보낸 글을 찾음) · *채팅 입력함·올라감 미확인*(위치 클릭 방식 등) · *문자 보냄*.
   퀴즈 답은 채팅·문자로만 보내며 게시판에는 올리지 않습니다.

### 사연 (공감로그)
- 진행자가 "오늘의 주제는 ○○, 사연 보내 주세요"처럼 주제를 주면, '실제로 있었던 일'로 확인한 내 경험 중 맞는 것을 골라 공감로그용 200자 이내 글을 만듭니다. 맞는 경험이 없으면 쓰지 않고 주제만 알려 줍니다(직접 써서 보낼 수 있음). **없는 일을 지어내지 않습니다.**
- Claude에 보내기 전 '공개하지 않을 단어'와 경험별 '가릴 내용'은 ○○로 가립니다. 개인정보·재료에 없는 소재·숫자·인용을 검사합니다.
- *사연 자동 전송* 을 켜면 **검사 경고가 하나도 없는 글만** 바로 보냅니다. 직접 써 둔 '공감로그용 한 줄'은 언제나 그대로 보냅니다.
- **승인한 사연은 확인 없이 보냅니다** (0.34, 청취 화면 *승인한 사연은 확인 없이 보내기* — 기본 켬): 사연은 '실제로 있었던 일'로
  확인한(고친) 경험으로만 쓰므로, AI가 다듬은 글에 경고가 나도(재료에 없는 숫자·대사·내용, 실명 등) 확인 대기에 두지 않고
  **내가 승인한 글 그대로** 보냅니다 — 공감로그용 한 줄이 있으면 그것, 없으면 본문을 문장 단위로 200자 안에
  ("제 와이프 이야기인데요, …"처럼 주인공 호칭으로 시작). 게시판 자동 등록도 같아서, 원고를 승인한 글 그대로(제목은 경험 이름,
  마무리까지)로 바꿔 등록합니다. AI가 덧붙인 내용은 보내지 않습니다. 끄면 예전처럼 확인 대기에 남깁니다.
- 한 번 보낸 경험은 **같은 방송국(SBS·MBC·KBS)에 다시 보내지 않습니다.** 다른 방송국에는 보낼 수 있습니다 (예: SBS 파워FM에 보낸 경험은
  러브FM·SBS 게시판에는 다시 안 쓰고, MBC·KBS에는 씀). 보냈는지 모르는 글(결과 불명)도 보낸 것으로 봅니다.
- **사연 → 보낸 사연 목록**: 앱 채팅·문자·게시판으로 보낸 글을 방송국별로 모아 보고, 경험마다 어느 방송국에 보냈는지(✓) 표로 봅니다.
- 확인할 글이 생기면 메뉴에 건수가 빨갛게 표시되고 알림음이 납니다. 메뉴 옆 **✓ 확인함**(또는 퀴즈 기록·사연 화면의 *알림 확인함*)을 누르면
  숫자가 사라집니다. 확인 대기 글은 목록에 그대로 남고(첫 화면 '확인 대기' 칸 숫자도 그대로), 그 뒤에 새로 생긴 글만 다시 숫자로 뜹니다.

### 증거 사진 (메뉴 '증거 사진')
퀴즈 정답·사연을 보낼 때마다 화면을 찍어 남기고, 메뉴 **증거 사진**에서 날짜·종류(퀴즈 정답 / 사연 / 게시판)별로 봅니다. 사진을 누르면 크게 열립니다.
- **채팅 앱(고릴라·mini·콩)**: 보낸 직후 앱 창 1장 (채팅 목록에 내 글이 보이는지). 오클릭 방지로 보내지 못했을 때도 그때 창을 찍습니다.
- **휴대폰 문자**: 문자 작성 화면(받는 번호·글) + 보낸 뒤 화면, 2장.
- **게시판**: 입력을 마친 글쓰기 화면(등록 누르기 전) + 등록 뒤 화면(글 주소), 2장.
- **전송 테스트**: 누르기 직전(빨강·초록 원 = 누른 자리) + 보낸 뒤 화면. 보내지 못했으면 그때 화면에 누를 자리를 표시해 남깁니다 ('전송 테스트' 종류).
- **퀴즈 기록·보낸 사연·제출 이력**의 각 줄에 **📷 증거 ○장**이 붙어 그 글의 사진만 바로 볼 수 있습니다.
- 사진은 데이터 폴더의 `evidence\년-월\` 에 JPEG로만 저장되고 어디로도 보내지 않습니다 (Claude 분석에도 쓰지 않음).
  화면에 다른 청취자 닉네임·휴대폰 화면이 찍히니 공유할 때 주의하세요. 이번 업데이트 전에 보낸 글은 사진이 없습니다.

   확인 사진(`rainbow_found.png`)에서 파란 네모가 입력칸, 초록 네모가 전송 단추에 있는지 확인하세요.
4. 청취 시작에서 CBS 채널을 고르거나, 동시 청취의 보조 칸에 넣습니다.

- 채널 목록을 저장해 둔 PC 는 처음 켤 때 CBS 채널을 한 번 더해 줍니다 (이미 지웠으면 다시 넣지 않음).
  문자 번호는 위키백과 등에서 확인한 것만 넣었습니다. 프로그램마다 다를 수 있으니 방송 안내와 다르면 설정에서 고치세요.
- 편성표: 프로그램 화면의 **MBC·KBS·CBS 편성표 가져오기**가 CBS 편성도 웹에서 찾습니다 (일주일마다 저절로).
- 게시판 사연: 코너 → **코너 주소로 추가**에 cbs.co.kr 의 https 게시판 주소도 넣을 수 있습니다 (자동 입력 허용 주소에 추가).
- 같은 경험은 같은 방송국에 한 번만 보냅니다 (CBS 도 따로 셈).
- **레인보우 소리 0 (0.61)**: 장치 점검에서 볼륨 믹서 측정도 0 이면 도우미가 아니라 레인보우가 소리를 내지 않는 것입니다.
  ① 레인보우에서 재생(▶)을 눌러 귀에 들리는지 보고, ② 들리지 않으면 볼륨 믹서에서 레인보우의 출력 장치를 **다른 채널 앱이
  소리 나는 장치**(장치 점검이 이름을 알려 줌, 예: LG ULTRAFINE)로 직접 지정하세요. '기본값'은 윈도우 기본 스피커를 따라가므로,
  장치 점검에 나오는 *윈도우 기본 스피커*가 가상 장치(CABLE)면 '기본값'으로 둔 앱 소리는 들리지 않습니다 — 이때는 윈도우 설정 →
  시스템 → 소리 → 출력에서 실제 스피커를 고르세요 (가상 오디오를 설치하면 윈도우가 기본 장치를 바꿔 두는 경우가 있음).
- EBS 반디는 0.56 에서 뺐습니다. 0.55 가 채널 목록에 저절로 더했던 `EBS FM` 줄(과 그 채널을 넣은 동시 청취 칸)은 한 번 지웁니다.
  직접 넣은 EBS 채널은 그대로 두며, 앱 채팅 없이 듣기·받아쓰기·문자로만 씁니다.

## 동시 청취 — 한 PC 에서 여러 채널 (0.53~0.61, 첫 화면 → 동시 청취)

방송국마다 앱이 달라(SBS 고릴라 · KBS 콩 · MBC mini · CBS 레인보우) 네 채널까지 한 PC 에서 함께 듣고,
채널마다 받아쓰고 보냅니다 (주 채널 + 보조 2~4 칸).
한 앱은 한 번에 한 채널만 재생·채팅하므로 **같은 앱 채널 둘**(예: 파워FM + 러브FM)은 함께 고를 수 없습니다.

**앱 소리 직접 받기 — 설치 필요 없음 (0.54·0.56, 윈도우 11 등)**
윈도우의 *프로세스 루프백*으로 앱(과 그 앱이 띄운 하위 프로세스)이 내는 소리만 따로 녹음합니다. 모든 앱이 같은
스피커로 나와도 섞이지 않으므로 가상 오디오 장치도, 볼륨 믹서 설정도, 녹음 장치 고르기도 필요 없습니다.
- 0.56: 동시 청취를 켜면 **녹음 장치 칸에 무엇을 적어 두었든 앱마다 소리를 직접** 받습니다. 0.55 에서 칸마다 장치(스피커·S/PDIF·
  모니터)를 골라 두면, 모든 앱이 스피커로 나오므로 다른 장치 칸은 *소리 0*, 스피커 칸은 여러 방송이 섞여 받아쓰기가 안 됐습니다.
  출력 장치로 나눠 녹음하려면(가상 장치·볼륨 믹서를 직접 쓸 때만) *고급: 출력 장치로 나눠 녹음*을 켭니다.
- 0.56: 앱 창의 프로세스가 아니라 **볼륨 믹서에 보이는 '소리를 실제로 내는 프로세스'**를 찾아 녹음합니다
  (소리를 하위·별도 프로세스가 내는 앱도). 아직 재생 전이면 앱 창의 맨 위 프로세스를 하위까지 함께 녹음합니다.
- 0.57·0.59: 장치 점검이 DB 연결 오류(`SQLite objects created in a thread …`)로 모든 칸을 '확인 필요'로 보이던 문제를
  고쳤습니다 (0.57 은 앱 찾기만 고쳐서 0.58 까지 남아 있었음 — 녹음기를 칸마다 스레드에서 만들며 설정을 읽었음).
  청취 자체는 영향 없었습니다. 볼륨 믹서에서도 그 앱 소리가 0 이면 "앱이 소리를 내지 않고 있다"고 알려 줍니다.
- 0.59: '지금 소리 내는 프로그램'에 앱마다 **소리가 나가는 출력 장치**도 봅니다. 기본 스피커가 아닌 장치(예: `CABLE In 16ch`)로
  나가는 앱은 노란 이름표로 표시하고, 그 앱 칸이 소리 0 이면 볼륨 믹서에서 출력 장치를 '기본값'으로 돌리라고 알려 줍니다.
- 상태 표의 *소리 0* 은 그 칸이 지금 아무 소리도 못 받고 있다는 뜻입니다 (정상이 아님). 녹음 장치 칸 아래에 실제로 녹음하는
  프로세스(예: `gorealra.exe 앱 소리`)가 나옵니다.
1. 들을 앱(고릴라·콩·mini·레인보우)을 켜고 각각 채널을 재생합니다 (소리가 스피커에서 함께 들립니다).
2. 첫 화면 **동시 청취**: *동시 청취 켜기* → 보조 2~4 칸에 채널만 고르고 **저장**.
   주 채널은 *청취 시작*에서 고른 채널입니다.
3. **장치 점검 (10초)**: 모든 채널을 10초 동시에 녹음해 채널마다 소리 크기와 받아쓴 말을 보여 줍니다.
   함께 **지금 소리 내는 프로그램**(볼륨 믹서의 앱별 소리 크기)을 재서, 앱이 소리를 안 내는지(재생·로그인 확인)
   앱은 소리를 내는데 받지 못하는지(이 PC 의 앱 소리 받기 문제 — 화면을 찍어 보내 주세요)를 가려 알려 줍니다.
4. 설정 → 앱 채팅·인식 설정 → **모든 앱 찾기**로 앱마다 입력칸·전송 버튼·채팅 영역을 찾아 둡니다
   (앱마다 로그인은 직접). 앱 소리를 받을 때도 여기서 찾아 둔 프로그램 이름으로 앱을 찾습니다.
- 앱을 껐다 켜도 소리가 끊긴 것을 알아채면 다시 찾아 이어서 녹음합니다.
- 스피커 볼륨을 줄여도 앱 소리가 계속 잡히는지는 PC 마다 다를 수 있습니다 — 줄인 뒤 장치 점검으로 확인하세요.
  앱 안의 볼륨·음소거는 녹음에도 그대로 들어갑니다.
- 한 채널만 들을 때(동시 청취 끔)는 예전처럼 기본 스피커를 녹음합니다.

**앱 소리 받기가 안 되는 PC — 가상 장치 자동 설치 (무료 VB-CABLE)**
윈도우 10 의 오래된 판처럼 앱 소리를 직접 받지 못하면, 앱마다 소리를 다른 출력 장치로 나눕니다.
1. 동시 청취의 **가상 장치 자동 설치 (무료 VB-CABLE)** 를 누릅니다. 공식 사이트(vb-audio.com)에서 무료 VB-CABLE 을
   내려받아 설치 파일 서명이 VB-Audio 것인지 확인한 뒤 관리자 권한으로 설치 창을 엽니다. 윈도우가 묻는
   *이 앱이 디바이스를 변경하도록 허용* · *장치 소프트웨어 설치* 는 직접 **예 · 설치** 를 누릅니다. 끝나면 PC 를 다시 켭니다.
   (VB-CABLE 은 기부형 무료입니다. 장치 2개짜리 *A+B* 는 기부해야 받을 수 있어 쓰지 않습니다.)
2. 윈도우 **설정 → 시스템 → 소리 → 볼륨 믹서**에서 앱마다 **출력 장치**를 고릅니다. 예) 고릴라 → 스피커, 콩 → `CABLE Input`.
   무료 장치는 하나라 세 번째 채널은 모니터(HDMI) 소리처럼 이미 있는 다른 출력 장치가 있을 때만 됩니다.
3. 동시 청취 칸에 같은 장치 이름을 적고 저장 → **장치 점검**. 두 장치에 같은 소리가 들어오면(앱별 출력이 안 나뉨) 알려 줍니다.

**돌아가는 방식**
- *청취 시작*을 누르면 주 채널은 예전처럼, 보조 채널은 칸마다 따로 청취기를 띄웁니다 (꺼지면 저절로 다시 띄움).
  받아쓰기·자막 기록·퀴즈와 사연 감지·DJ 한마디·신청곡이 채널마다 따로 돌고, 자막·기록 줄 앞에 `[채널]` 이 붙습니다.
- **보내기는 하나씩 차례로**: 마우스·키보드는 하나라서, 여러 채널이 동시에 보내려 하면 입력 잠금으로 순서를 기다립니다.
  같은 정답을 두 청취기가 함께 보내지 않도록 먼저 잡은 쪽만 보냅니다.
- 시간당 보내기 상한(퀴즈·사연)은 **채널마다** 따로 셉니다.
- 0.58: 보내기 차례(화면·마우스)를 못 잡으면(다른 칸이 보내는 중·게시판 입력 중) 아무것도 누르지 않은 것이므로
  **대기 → 1분마다 다시 시도**합니다 (예전에는 '결과 불명'으로 끝나 다시 보내지 않았음). 차례는 60초까지 기다립니다.
  보내는 도중 프로그램을 끄면 남던 잠금 파일은, 만든 프로그램이 꺼졌으면 바로 지웁니다 (예전에는 80분 동안 모든 전송이 막힘).
  채팅 창 자동 다시 찾기도 차례가 비어 있을 때만 해서, 다른 칸이 입력하는 중에 창을 앞으로 가져오지 않습니다.
- 첫 화면 **최근 못 보낸 퀴즈·사연**: 최근 6시간에 아직 못 보냈거나 결과를 모르는 글과 그 이유를 보여 줍니다.
- 동시 청취를 끄거나 청취를 멈추면 보조 청취기도 1분 안에 스스로 끝납니다.
- 같은 채널 두 번 · 같은 앱 두 채널 · 같은 녹음 장치 두 칸은 저장·청취 시작에서 막고 이유를 보여 줍니다.

**그래픽카드** — 채널마다 받아쓰기 모델을 하나씩 올립니다. large-v3(그래픽카드 기본)는 채널당 약 3~4GB 라 RTX 5070 Ti(16GB)면
세 채널까지 함께 돌릴 수 있고, **네 채널**이면 모델이 auto 일 때 저절로 large-v3-turbo(채널당 약 2GB)를 씁니다. **그래픽카드 다시 점검** 버튼은 저장해 둔 점검 결과를 지우고 지금 다시 시험해,
*그래픽카드* 인지 *CPU* 인지와 실패 이유를 보여 줍니다. 받아쓰기가 10초 녹음에 20초 넘게 걸리면 CPU 로 돌고 있는 것입니다.
- **RTX 50 시리즈(5070·5080·5090, Blackwell)** 는 받아쓰기 엔진 `ctranslate2` 4.6.3 이상과 `nvidia-cublas-cu12` 12.8 이상이
  있어야 그래픽카드로 돕니다. 예전 판이 깔려 있으면 점검에 실패해 CPU 로 돌았습니다 — 0.53 의 `start_windows.bat` 이 다시 켤 때
  두 부품을 올리고, 판이 바뀌면 그래픽카드 점검도 저절로 다시 합니다.
- 그래픽카드 없이(CPU) 여러 채널을 받아쓰면 녹음보다 느릴 수 있습니다. 장치 점검이 이를 알려 주며, 그때는 설정에서
  음성 인식 모델을 `small` 로 낮추세요.

**모든 라디오가 함께 끊길 때 (0.61)**
한 앱이 아니라 모든 라디오가 같이 조용해지면 원인은 앱들이 함께 쓰는 것 — 출력 장치·화면·그래픽카드·인터넷 — 입니다.
- **듣는 동안 화면 꺼짐·절전을 막습니다** (첫 화면 청취 옵션 *듣는 동안 화면 꺼짐·절전 막기*, 기본 켬). 라디오 앱 소리가
  모니터 스피커(예: `LG ULTRAFINE (NVIDIA High Definition Audio)`, 그래픽카드 HDMI·DP 소리)로 나가면, 윈도우가 정한 시간
  (예: 20분) 동안 키보드·마우스를 안 쓸 때 화면을 끄면서 모니터가 대기 상태로 들어가 **모든 라디오 소리가 함께 끊깁니다**.
  동영상 재생기처럼 듣는 동안만 윈도우에 '화면 필요'를 알리고, 청취를 멈추면 원래대로 돌아갑니다.
- **소리 끊김 기록에 원인 자료**를 덧붙입니다: 그 채널 앱이 지금 소리를 내는지(앱은 소리를 내는데 녹음만 끊겼으면 다시 연결),
  볼륨 믹서의 앱별 소리·출력 장치, 소리 내는 라디오 앱이 하나도 없는지(공통 원인), 윈도우 기본 스피커, 마지막 키보드·마우스 입력이
  몇 분 전인지, 최근 10분 안에 **그래픽카드 드라이버가 다시 시작**됐는지(윈도우 시스템 기록 'Display' 4101 — 이때 모니터 스피커 소리가
  끊기고 앱이 재생을 멈출 수 있음). 다음에 끊기면 첫 화면 *최근 감지·전송* 의 '소리 끊김' 줄을 찍어 보내 주세요.
- 도우미가 앱 소리를 받는 방식(프로세스 루프백)은 윈도우가 앱 소리를 복사해 주는 것이라 앱 재생을 바꾸거나 멈추지 않습니다.

**모니터 두 대 이상 (0.60)**
채팅 앱을 보조 모니터에 두어도 입력됩니다. 예전에는 클릭 도구(pywinauto)가 마우스 위치를 주 모니터 크기로 바꿔 계산해,
보조 모니터의 입력 칸을 누르면 커서가 주 모니터 가장자리로 가 버렸습니다. 이제 커서를 그 자리로 직접 옮긴 뒤 누르고,
옮겨지지 않았으면 엉뚱한 곳을 누르지 않고 '마우스를 옮기지 못함'으로 실패를 남깁니다 (다시 시도 대상).
채팅창 위치·크기는 여전히 건드리지 않습니다.

## 안전장치

- **확인 안 된 조건 = 대기**: 모집 중 확인, 공지 확인 기록, 마감, 제출 대상 지정, 사용자 승인, 사실 확인, 실제 경험 확인 중 하나라도 없으면 실제 화면 입력 버튼이 꺼집니다.
  (게시판 자동 등록은 방송에서 게시판 사연을 받는다고 한 것을 모집 중으로 보고, 사용자 승인·사실 확인 대신 **검사 경고 0건**을 요구합니다.)
- **첫 대상은 '사연과 신청곡' 한 곳**만 제출 대상으로 지정되어 있습니다.
- **한 경험은 방송국마다 한 번**: 같은 경험이 *입력만 함 / 등록 확인 / 결과 불명* 상태로 같은 방송국 이력에 있으면 다시 보내지 않습니다 (게시판은 SBS).
- **결과 불명은 재전송하지 않음**: 입력 후 글쓰기 화면을 벗어나면 *결과 불명* 으로 기록하고, 게시판 확인 전까지 같은 경험을 막습니다.
- **공지 변경 감지**: 붙여 둔 공지 원문이 바뀌면 재검토 전 제출 중지.
- **일괄 중지**: 설정 화면 버튼 하나로 모든 입력 작업을 막습니다.
- **입력 직렬화**: 입력 작업은 한 번에 하나만 실행됩니다.
- **채팅 앱 오클릭 방지**: 누를 자리를 다른 창이 가리거나, 창 크기·자리가 위치 지정 때와 다르거나, 앱 창이 맨 앞이 아니면 누르지도 키를 보내지도 않습니다.
- **허용 주소**: 실제 입력은 `https://programs.sbs.co.kr`, `https://m.programs.sbs.co.kr` 글쓰기 화면에서만 합니다.
- **관리 화면 접속**: 이 PC(127.0.0.1)와 원격 주소(radio.haetsallab.com, 로그인 필요)에서만 열리고, 다른 주소로 온 요청과
  외부 사이트가 보낸 위조 요청은 거부합니다.

## 밖에서 보기 · 자동 업데이트 (0.36, 메뉴 설정 → 원격 접속·업데이트)

### 밖에서 관리 화면 보기 — https://radio.haetsallab.com
- 휴대폰·다른 PC에서 이 주소를 열면 **이 PC에서 돌고 있는 관리 화면**이 열립니다 (Cloudflare Tunnel — 공유기 설정 없음).
  PC가 켜져 있고 도우미가 돌고 있어야 합니다.
- **처음 한 번 설정** (화면 안내와 같음):
  1. Cloudflare → Zero Trust → Networks → Tunnels → Create a tunnel(Cloudflared) → 이름 `radio-helper`.
  2. Windows 를 고르면 나오는 `cloudflared.exe service install …` 명령을 이 PC의 관리자 명령 프롬프트에 붙여 넣습니다.
     명령 안의 토큰은 비밀번호와 같으니 채팅·메신저·GitHub 에 올리지 마세요 (이 도우미도 받지 않음). PC를 켜면 터널이 저절로 켜집니다.
  3. Public Hostname: `radio` . `haetsallab.com` → Service `HTTP` · `localhost:5000`.
  4. (권장) Zero Trust → Access → Applications → Self-hosted 로 `radio.haetsallab.com` 에 내 이메일만 허용하는 정책을 걸면,
     도우미 비밀번호 앞에 Cloudflare 이메일 인증이 한 번 더 붙습니다.
  5. 화면의 **밖에서 연결되는지 확인**이 '연결됨'이면 끝.
- **원격 접속 비밀번호**는 PC 앞에서만 정하고 바꿉니다 (8자 이상). 원본은 저장하지 않고 PBKDF2 해시만 데이터 폴더에 둡니다.
  밖에서 열면 로그인 화면이 먼저 나오고(14일 유지), 5번 틀리면 15분 잠깁니다. 비밀번호를 바꾸면 밖의 로그인은 모두 풀립니다.
  비밀번호를 정하기 전에는 밖에서 열어도 '원격 접속이 꺼져 있습니다'만 보입니다. 로그인·실패 기록에는 접속한 곳(IP)만 남습니다.
- 밖에서도 청취 시작·멈춤, 퀴즈·사연 확인, 증거 사진, 업데이트 등 PC 앞과 같은 화면을 씁니다 (비밀번호·원격 주소 변경만 PC 앞에서).
- 관리 화면이 5000번이 아닌 번호로 켜지면(예전 검은 창이 5000번을 쓰는 중) 터널이 닿지 않으니 화면에 경고가 나옵니다.

- **밖에서 안 열릴 때** (0.46): 업데이트·오류 뒤 다시 켤 때 방금 꺼진 관리 화면이 5000번을 늦게 놓으면, 예전에는 바로 5001번으로
  켜져 터널(→ 5000번)과 어긋났습니다. 이제는 5000번이 빌 때까지 최대 1분 기다리고, 그래도 다른 번호로 켜졌으면 5000번이 비는 대로
  그 번호로도 열어 저절로 다시 이어집니다. 설정 → 원격 접속의 *관리 화면 번호*·*밖에서 연결되는지 확인*으로 상태를 볼 수 있습니다.
  브라우저에 Cloudflare 오류가 보이면: **502 Bad Gateway** = 터널은 연결됐지만 터널이 넘겨주는 곳에 관리 화면이 없음
  (주소를 서버 터널·127.0.0.1:5002 로 옮겼는데 서버 배포 전 / PC 검은 창 꺼짐·다른 번호),
  **1033 / Tunnel error** = cloudflared 서비스가 꺼짐(또는 PC 가 꺼짐·절전), **주소를 찾을 수 없음** = Cloudflare 에서 이 주소(Public Hostname)가 빠짐.
- 서버용 `.env`(`RADIO_HELPER_SERVER=1` 이 적힌 파일)가 PC 프로그램 폴더에 있어도 PC 는 그 안의 `PORT`·`TZ` 등을 따르지 않습니다.

### 자동 업데이트
- 새 버전은 **GitHub(이 저장소)** 에서 받습니다 — radio.haetsallab.com 은 이 PC로 이어지는 주소라 업데이트 파일을 두는 곳이 아니라
  **어디서든 업데이트를 보고 누르는 곳**입니다. 6시간마다 새 버전을 확인하고(`VERSION` 번호가 올라간 것만),
  *새 버전이 나오면 자동으로 업데이트* (기본 켬, 새벽 4시 — 시각은 바꿀 수 있음) 또는 **지금 업데이트** 버튼으로 설치합니다.
- 프로그램 파일만 바꿉니다: `.venv`·데이터 폴더(경험·사연·설정)는 그대로. 바뀌는 파일은 데이터 폴더 `updates\backup-…` 에 먼저 모아 둡니다.
- 설치가 끝나면 관리 화면이 종료 코드 3 과 표시 파일(`update_restart.flag`, 윈도우의 '경로 없음' 코드 3 과 구별)로 끝나고 `start_windows.bat` 이 패키지를 확인한 뒤 다시 켭니다.
  듣던 방송은 묻지 않고 이어서 듣습니다 (1~2분 끊김). 실행 중인 `start_windows.bat` 은 바로 바꾸지 않고 `start_windows.new.bat` 으로
  받아 두었다가 다시 켤 때 스스로 바꿉니다.
- **되돌리기**: 새 버전이 켜지자마자 3번 연속 꺼지면 `start_windows.bat` 이 `rollback_update.py` 로 예전 파일을 되돌리고,
  그 버전은 다시 받지 않습니다. 새 버전이 2분 넘게 잘 돌면 '확인됨'으로 표시되어 그 뒤에는 되돌리지 않습니다.
- 자동으로 다시 켜지는 것은 `start_windows.bat` 으로 켰을 때만입니다. 0.36 은 이 기능이 처음 들어간 버전이라 한 번은 직접 덮어써야 합니다.

## Claude 구독으로 쓰기 (0.45, 설정 → Claude 연결)

퀴즈·사연·공지 분석과 MBC·KBS 편성표 찾기를 **API 키(충전 요금)** 대신 **Claude 구독(Pro·Max)** 으로 합니다.
이 PC 에 설치한 공식 **Claude Code** 에 claude.ai 계정으로 한 번 로그인해 두면, 프로그램이 Claude Code 를 화면 없이 실행해 결과만 받습니다.

1. Claude Code 설치 — 명령 창(PowerShell)에서 `irm https://claude.ai/install.ps1 | iex`
2. 로그인 — 설정 → Claude 연결의 **Claude Code 로그인** 버튼(또는 명령 창에서 `claude auth login`) → 브라우저에서
   **claude.ai 계정(구독)** 으로 로그인 → 검은 창 닫기. **claude.ai 웹·Claude 데스크톱 앱에 로그인되어 있어도 Claude Code 는 따로
   한 번 로그인해야 합니다.** (Console 계정·API 키로 로그인하면 충전 요금에서 나갑니다. *연결 확인*이 알려 줍니다.)
   로그인한 뒤 설정 화면을 열면 저절로 다시 확인합니다.
3. 설정 → Claude 연결 → **연결 확인** (PC 는 Claude 구독이 기본으로 골라져 있음. 설치·로그인 방식만 확인, 모델은 부르지 않음)

- 사용량은 **claude.ai 채팅·Claude Code 와 함께 쓰는 5시간·주간 한도**에서 나갑니다. 한도에 걸리면 풀릴 때까지 분석을 못 하고
  (10분마다 다시 시도), *구독 한도에 걸리거나 로그인이 풀리면 API 키로 이어서*를 켜 두면 그동안만 API 키(충전 요금)로 대신합니다
  (기본 꺼짐, 대신한 일은 작업 기록에 남음).
- 로그인 정보(토큰·비밀번호)는 Claude Code 가 스스로 보관하고, 이 프로그램은 읽거나 저장하거나 넘기지 않습니다.
  Claude Code 를 실행할 때는 `ANTHROPIC_API_KEY` 를 빼고(있으면 구독 대신 그 키로 결제됨), 빈 임시 폴더에서 도구를 모두 끈 채
  실행합니다 (편성표 찾기만 웹 검색). 대화 기록은 남기지 않습니다.
- Claude Code 를 한 번 거치므로 분석 1회가 몇 초 더 걸립니다.
- Max 요금제는 매달 API 크레딧이 함께 나오므로(Console 에 연결된 조직), 그 크레딧으로 API 키 방식을 그대로 써도 됩니다.
- 서버 모드는 Claude Code 가 보통 없어서 기본이 API 키(`.env` 의 `ANTHROPIC_API_KEY`)입니다. 서버에서도 구독으로 쓸 수 있습니다: 서버에 `ubuntu` 사용자로 Claude Code 를 설치하고(`curl -fsSL https://claude.ai/install.sh | bash`)
  `claude` 로 한 번 로그인한 뒤 같은 설정을 고릅니다.

## 코너 게시판 자동 등록 — 방송국 상관없이 (0.43, 메뉴 코너 → 코너 주소로 추가)

- 같은 방송국에는 같은 경험을 다시 보내지 않습니다 (게시판·채팅·문자 모두 합쳐서, 결과 불명이어도). 다른 방송국에는 보낼 수 있습니다.
- 공지 화면에서 같은 프로그램의 다른 코너(매일코너·요일코너)를 찾아 주면 골라서 한 번에 추가합니다.

### 매일 게시판 확인 (0.60, 코너 화면 맨 위)

'**매일 게시판 확인**'을 켜 두면 (0.60 처음 실행 때 한 번 켜짐, 시험부터) 정한 시각(기본 10:30)에 게시판이 있는 코너를 **하루 한 번씩** 돌아봅니다.
코너마다 정한 '매일 자동'이 있으면 그 시각·요일이 먼저입니다.

- **아직 올리지 않은 게시판**이거나 **공지가 새로 바뀐 게시판**에만 올립니다. 지금 공지로 이미 올린 게시판은 '새 공지가 올라오면 다시 올립니다'로
  건너뜁니다. 공지는 Claude 가 매번 옮겨 적어 글이 조금씩 달라지므로 원문이 80% 넘게 같으면 같은 공지로 봅니다.
  0.60 전에 이미 올린 게시판은 첫 확인 때 '이미 올림'으로 적어 두고 다시 올리지 않습니다.
- **게시판 글은 채팅보다 깁니다**: 채팅용 한 줄 대신 확인한 사연 전체를 '안녕하세요. — 본문 — 늘 감사합니다.' 모양으로 씁니다
  (공지 글자 수 안에 들 때만 인사·맺음을 붙이고, 사실은 덧붙이지 않음). '짧은 한마디' 코너는 예전처럼 짧게 씁니다.
- 브라우저 프로필이 하나라 **한 번에 한 코너씩** 차례로 돌고, 하루 **최대 5건**(코너 화면에서 바꿈, 0 = 무제한)까지만 올립니다.
- **시험(입력만)** 이 기본입니다: 글쓰기 칸에 입력하고 증거 사진만 남기며 등록은 누르지 않습니다. 증거 사진 1~2장을 보고 괜찮으면
  '시험'을 끄면 그다음부터 등록까지 누릅니다. 시험 입력만 한 공지는 '등록까지'로 바꾼 뒤 실제로 다시 올립니다.
- **미리 로그인**: 코너 화면 **미리 로그인 (도우미 브라우저 창 열기)** → 방송국마다 탭이 열리면 직접 로그인하고 창을 닫습니다 (20분 대기).
  **로그인 상태 확인**은 창 없이 방송국별 로그인 여부를 다시 봅니다. 아침 확인 중 로그인이 풀려 있으면 '로그인 필요'로 표시하고
  그 코너는 건너뜁니다 (창 없이 도는 매일 확인에서는 로그인 창을 띄우지 않음).
- **Aside 등 다른 브라우저의 로그인은 빌려 쓰지 않습니다**: 그 브라우저의 로그인 정보(쿠키)는 암호화돼 있고, 크로미움은 평소 쓰는
  프로필을 자동화하지 못하게 막으며, 이 도우미는 세션·쿠키를 옮겨 담지 않습니다. 대신 도우미 전용 브라우저에서 한 번 로그인하면
  그 프로필에 남아 다음부터 창 없이 등록합니다. 비밀번호는 이 프로그램이 읽거나 저장하지 않습니다.

  듣기·자막 창·도구는 Ctrl+C 를 받아도 꺼지지 않고, '청취 시작' 중에 듣기 실행기가 꺼지면 관리 화면이 30초 안에 다시 켭니다(30분에 5번까지).
  켜지고 꺼진 기록과 원인은 `logs/server.log`(파이썬 밖에서 꺼지면 `logs/server_crash.log`)에 남고,
  다시 켜지면 첫 화면 '최근 감지·전송'에 표시됩니다. 검은 창 자체를 닫으면 청취도 함께 멈추니 닫지 말고 최소화하세요.
- 관리 화면에서 오류가 나면 'Internal Server Error' 대신 **주소·오류·위치와 해결 안내**가 화면에 나오고, 전체 내용은 `logs/errors.log` 에 남습니다.
  그 화면을 캡처해 보내면 원인을 바로 찾을 수 있습니다.
- 여러 작업(관리 화면·청취·자막 창·목록 다시 읽기·풀어 쓰기)이 한 데이터 파일을 함께 씁니다. 오래 걸리는 작업은 웹 페이지를 여는 동안
  데이터를 잠그지 않으며, 잠깐 잠겨도 청취·자막 창은 꺼지지 않고 다시 시도합니다.
- 개발·시험용으로 다른 위치를 쓰려면 환경 변수 `RADIO_HELPER_DATA_DIR` 를 지정합니다.
- 방송 녹취(글자)는 데이터베이스에 남고, 오디오는 저장하지 않습니다.

## 개발

```bash
python -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m pytest
```

모의 화면 종단 테스트는 Chromium이 있으면 실행됩니다 (`RADIO_HELPER_CHROMIUM=/path/to/chrome`).
퀴즈 자동 참여는 가짜 녹음·인식·분석·고릴라로 예약 구간과 '청취 시작' 전체를 돌리는 테스트가 있습니다 (`tests/test_quizbot.py`, `tests/test_live.py`).
윈도우 전용 부분(`quizbot/audio.py` 녹음, `quizbot/gorilla.py` 화면 조작, `quizbot/captions.py` 자막 창)은 실제 PC에서만 동작합니다.
