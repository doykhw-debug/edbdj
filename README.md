# SBS 라디오 참여 도우미

이 PC에서만 돌아가는 SBS 라디오(파워FM·러브FM·고릴라M) 참여 도구입니다.

- **청취 시작 한 번**: 첫 화면의 **▶ 청취 시작**을 누르면 PC 소리를 자막으로 바꾸고, 자막에서 퀴즈·사연·선물 안내를 찾아
  고릴라 공감로그로 **퀴즈 정답과 사연을 자동으로 보냅니다**. 수집 중인지는 첫 화면과 항상 위에 뜨는 자막 창에서 바로 보입니다.
- **게시판 사연**: 본인의 실제 경험을 재료로 원고를 만들고, 검사·승인을 거쳐 게시판 글쓰기 화면에 **입력만** 합니다 (등록 버튼은 직접).

채널: SBS 파워FM·러브FM·고릴라M, MBC FM4U, KBS 쿨FM·해피FM·1라디오가 기본으로 들어 있고, 첫 화면 **채널 추가**로 늘릴 수 있습니다.
보내는 방법은 청취 화면에서 고릅니다: **앱 채팅**(SBS 고릴라·MBC mini·KBS 콩, 무료) 또는 **휴대폰 문자**(안드로이드 USB 연결, 건당 약 50원).

메뉴: **청취**(첫 화면) · **퀴즈 기록** · **사연** · **선물 기록** · **코너** · **프로그램** · **인물** · **내 정보** · **설정**

명세: [`docs/radio_participation_plan_20261002.md`](docs/radio_participation_plan_20261002.md)

## 사연: 하는 것 / 하지 않는 것

사연은 명세 4절의 검증 순서 중 **1~3단계**까지만 구현했습니다.

| 단계 | 내용 | 상태 |
|---|---|---|
| 1) 읽기 전용 점검 | 사용자가 직접 로그인한 글쓰기 화면에서 입력 요소·글자 제한 안내·CAPTCHA 흔적을 읽어 보고서로 남김 | 구현 (아무것도 입력·클릭하지 않음) |
| 2) 로컬 모의 화면 테스트 | 이 PC 안의 가짜 글쓰기 화면에 입력하고 모의 '등록'까지 시험 | 구현 |
| 3) 실제 화면 입력 | 승인된 원고를 실제 글쓰기 화면에 채워 넣기만 함 | 구현 — **등록 버튼은 사용자가 직접 누름** |
| 4) 실제 1건 제출 | 사용자가 직접 등록 버튼을 누르고 결과를 제출 이력에 기록 | 사용자 수동 |
| 5) 자동 실행 | 무검토 자동 제출 | **구현하지 않음** (규칙·허용 범위 미확인) |

하지 않는 것:
- 등록·임시저장 버튼 클릭 (실제 사이트에서는 코드에 클릭 경로 자체가 없음 — 테스트로 확인)
- 로그인·CAPTCHA·추가 인증 처리 또는 우회
- 비밀번호·쿠키·세션 토큰 저장 (브라우저 창을 닫으면 로그인도 사라짐)
- 사연 원고에 유료 AI API 연결 (원고 다듬기는 쓰던 대화형 AI에 요청문을 붙여 넣는 방식)
- 다른 청취자 사연 수집

## 설치·실행 (Windows)

1. [Python 3.11 이상](https://www.python.org/downloads/)을 설치합니다. 설치 화면에서 **"Add python.exe to PATH"** 를 체크하세요.
2. 이 폴더의 **`start_windows.bat`** 을 더블클릭합니다.
   - 처음 한 번은 필요한 패키지(음성 인식 포함)를 설치하느라 몇 분 걸립니다.
   - 브라우저에 관리 화면(`http://127.0.0.1:5000`)이 열립니다. 이 PC에서만 접속됩니다.
3. 끝낼 때는 검은 창에서 `Ctrl + C` 를 누르거나 창을 닫습니다.
4. **업데이트**: 새 압축 파일은 기존 폴더에 덮어써도, 새 폴더에 풀어도 됩니다. 경험·사연·설정은 프로그램 폴더 밖
   (`C:\Users\<이름>\AppData\Local\RadioHelper`)에 저장되어 그대로 남습니다. 예전 버전 폴더(`data/`)에 있던 데이터는
   처음 실행할 때 프로그램 폴더 → 같은 곳에 풀어 둔 다른 업데이트 폴더 → 내려받기·바탕 화면·문서 순으로 찾아, 가장 최근에 쓴 것을 한 번 옮겨 옵니다.

**관리 화면이 안 뜰 때**
- 검은 창의 `[점검]` 줄을 보세요. 서버가 뜬 것을 확인한 뒤 브라우저를 열고, 첫 화면이 실제로 열리는지 스스로 확인해 결과를 적습니다.
- 5000번을 예전에 켠 검은 창이나 다른 프로그램이 쓰고 있으면 `[알림]` 을 띄우고 5001, 5002… 다음 번호로 엽니다. 이때 주소는 검은 창의 **관리 화면:** 줄에 나온 주소입니다.
- 예전 검은 창은 예전 파일로 돌고 있을 수 있으니 닫으세요. 작업 표시줄에 검은 창이 여러 개면 하나만 남기세요.
- `[점검]` 이 실패라고 나오면 검은 창 전체를 캡처해 보내 주세요.

글쓰기 화면 입력에는 Windows에 기본 설치된 **Microsoft Edge**를 씁니다. 별도 브라우저 다운로드가 필요 없습니다.
(Edge 대신 Chrome을 쓰려면 환경 변수 `RADIO_HELPER_BROWSER_CHANNEL=chrome`)

macOS·Linux: `python3 -m venv .venv && .venv/bin/pip install -r requirements.txt && .venv/bin/python -m playwright install chromium && .venv/bin/python -m radio_helper`

## 사용 순서

1. **기본 정보** — 방송용 이름, 공개 가능한 지역·직업 표현, 가족 호칭, 문체, *본문에 나오면 안 되는 단어*(실명·회사명 등)를 정합니다.
2. **실제 경험** — 경험 1건마다 언제·누가·무슨 일·기억나는 말(정확한 인용인지 취지인지)·포인트·결말을 편하게 적고 *"실제로 있었던 일"* 을 체크합니다. 처음엔 3건이면 충분합니다.
3. **코너** — 공식 게시판 공지를 **직접 읽고** 모집 여부·마감·글자 제한·AI 보조 작성 제한 여부를 적은 뒤 *"공지 확인 완료"* 를 누릅니다. 공지 원문을 붙여 두면 다음에 공지가 바뀌었을 때 재검토 전까지 제출이 멈춥니다.
4. **원고 만들기** — 경험 화면에서 코너를 고르고 *원고 만들기* 를 누르면 템플릿 초안이 생깁니다(적은 문장을 그대로 배치하고 인사·맺음말만 붙임).
   더 매끄럽게 하려면 원고 화면의 **요청문 복사** → 쓰던 대화형 AI에 붙여넣기 → 받은 결과를 **결과 붙여넣기** 칸에 넣습니다.
5. **검사·승인** — 자동 검사(연락처·주소·금지어·재료에 없는 민감 소재·숫자·직접 인용·글자 수·이전 글과의 유사도)를 확인하고, 사건·인물·결과가 실제와 같다는 확인란을 체크해 승인합니다. 내용을 고치면 승인이 풀립니다.
6. **모의 화면 입력 시험** — 먼저 가짜 글쓰기 화면으로 흐름을 확인합니다.
7. **실제 화면 입력** — 코너 화면에서 *점검용 브라우저 열기* 로 글쓰기 화면의 입력 요소를 한 번 확인하고, 제목·본문 입력 요소를 코너 설정에 적어 둡니다. 그다음 원고 화면에서 *실제 화면에 입력하기* → 열린 브라우저에서 직접 로그인 → 도구가 내용을 채움 → **내용 확인 후 등록 버튼은 직접 클릭**.
8. **제출 이력** — 게시판에서 글이 올라간 것을 확인하면 상태를 *등록 확인* 으로 바꾸고 글 주소를 남깁니다. 사연 채택·당첨·상품 수령은 각각 따로 기록합니다.

## 프로그램 목록 (전 채널)

**프로그램** 화면에 채널별로 정리됩니다. 처음에는 파워FM 13개(01시 애프터클럽 ~ 23시 딘딘의 뮤직하이)와 러브FM 일부(이숙영의 러브FM)가 들어 있습니다.
처음 목록은 2026-10-02 웹 검색 결과로 확인한 것이라, **공식 페이지에서 새로고침**으로 이 PC에서 다시 확인하세요.

- 각 프로그램 공식 페이지에서 방송 시간·요일을 다시 읽고, 코너·게시판 링크를 **코너** 목록에 추가합니다(모집 여부는 '미확인').
- **코너** 화면의 **코너·게시판 모두 수집** 도 같은 작업입니다(3~5분). 코너 게시판(`…/cornerboards/번호`)은 그 페이지를 한 번 더 열어 코너 탭(`?cornerid=`)을 모두 모읍니다. 프로그램마다 최대 4곳까지 더 열어 봅니다.
  - 메뉴 링크뿐 아니라 페이지 글·받아 온 데이터에 적힌 게시판 주소도 모읍니다. 글 하나 주소(`?board_no=`)는 게시판 주소로 줄이고, 글 제목은 이름으로 쓰지 않습니다.
  - 이름을 못 읽은 게시판은 `(이름 확인 필요) 게시판 번호` 로 넣습니다. 코너 화면에서 열어 보고 **코너 이름** 을 고치세요.
  - 프로그램별로 찾은 개수가 칩으로 보이고, 노란색 0 은 아직 못 찾은 프로그램입니다. 실행 기록(`data/logs/programs_*.log`)에 프로그램마다 찾은 개수·읽은 링크 수가 남습니다.
  - 공식 페이지가 다른 주소로 넘어가면(프로그램 주소 변경) 넘어간 주소의 게시판도 그 프로그램 것으로 봅니다. 새로 편성에 넣은 프로그램의 게시판도 같이 모읍니다.
  - MBC·KBS 게시판은 다른 사이트라 모으지 않습니다(SBS만).
- SBS 라디오 첫 화면에서 목록에 없는 프로그램을 찾으면 그 페이지에서 **채널·방송 시간**을 읽어 편성에 넣습니다. 둘 중 하나라도 못 읽으면 '후보'로 남깁니다.
- 편성에 없는 시간에 청취해도 '러브FM 방송'처럼 채널 이름으로 기록하며 퀴즈·사연은 그대로 동작합니다.
- 페이지를 읽기만 하고 로그인·입력은 하지 않습니다. 시간을 읽지 못한 프로그램은 기존 값을 그대로 둡니다.

## 청취 시작 (원스텝)

라디오(고릴라)를 켜고 관리 화면 첫 화면 **청취**에서 듣는 채널을 고른 뒤 **▶ 청취 시작**을 누릅니다. 멈출 때는 **■ 청취 중지**.

- **눈으로 확인**: 첫 화면에 ● 수집 중(빨간 점 깜빡임)·소리 크기 막대·실시간 자막이 2초마다 갱신되고, 화면 오른쪽 아래에
  항상 위에 뜨는 작은 **자막 창**이 열립니다(닫아도 청취는 계속). 메뉴의 '청취' 옆 빨간 점은 청취 중이라는 뜻입니다.
- 상태 글: *시작하는 중* → *음성 인식 준비 중*(처음 한 번은 그래픽카드 점검과 모델 내려받기 약 1.6~3GB로 몇 분) → *수집 중*. 오류가 나면 그 내용이 상태 글과
  '최근 감지·전송'에 그대로 보이고 30초 뒤 다시 시도합니다.
- **마지막 녹음** 줄이 10초마다 바뀝니다(소리 크기·받아쓰기 시간·받아쓴 말, 말소리가 없으면 '말소리 없음'). 자막 칸에는 키워드와 상관없이 받아쓴 말이 전부 나옵니다.
- 실행기 신호가 끊기면 **응답 없음**(보라색)으로 바뀌고, 실행기 기록 파일 끝부분이 화면에 나옵니다. **↻ 다시 시작**으로 다시 띄웁니다.
  관리 화면을 다시 켜면 청취가 켜져 있던 경우 자동으로 이어서 듣습니다.
- **음성 인식 정확도** (고릴라·인식 설정, 기본은 모두 자동)
  - **장치 auto**: NVIDIA 그래픽카드가 있으면 `start_windows.bat` 이 그래픽카드 라이브러리(약 1GB, `requirements-gpu.txt`)를 함께 설치하고,
    실행기가 별도 프로세스로 그래픽카드를 한 번 점검한 뒤 되면 그래픽카드로 돌립니다. 점검에 실패하면 CPU로 돌리며(라이브러리 문제로 실행기가 꺼지는 일 방지),
    점검 결과는 저장해 두었다가 라이브러리가 바뀌거나 실패한 지 하루가 지나면 다시 점검합니다.
  - **모델 auto**: 그래픽카드면 `large-v3`, CPU면 `large-v3-turbo`(논리 코어 16개 미만이면 `small`)를 씁니다.
    예전 기본값(small·CPU)을 쓰던 PC는 업데이트 후 처음 켤 때 한 번만 자동으로 바뀝니다. 직접 고른 다른 값은 그대로 둡니다.
  - **겹쳐 듣기**: 10초 조각 끝 3초 안에서 시작한 말은 확정하지 않고 다음 조각과 이어서 다시 받아씁니다.
    조각 경계에서 말이 깨지거나 빠지는 일을 막는 대신, 그 말은 10초 늦게 자막에 나옵니다 (설정 '겹쳐 듣기' 0이면 끔).
  - **받아쓰기 후보 수**(기본 5): 여러 후보를 비교해 고릅니다. 받아쓰기가 녹음보다 느리다는 안내가 뜨면 1로 줄이세요.
  - **단어 힌트**: 퀴즈·초성 자음 이름(기역·니은…)·기프티콘 같은 방송 낱말과, 듣는 프로그램의 진행자·코너 이름을
    모델에 미리 알려 줍니다. 자주 틀리는 이름은 *음성 인식 단어 힌트* 칸에 쉼표로 적어 두세요.

### 인물 관계도 · 사연 보관함 (메뉴 '인물')
- **가져오기**에 인물 관계도 파일(`character-map.md`)을 넣으면 인물 카드와 실제 사건(연표)이 **인물**에 들어갑니다.
  가운데 '나'를 중심으로 묶음(우리 집·본가·처가·외가·직장·친구…)별로 그린 **관계도**와 **인물 목록**으로 봅니다.
- 인물마다 사연에 쓰는 **호칭**(예: 와이프, 대학 친구, 회사 동료)을 정합니다. 사연과 AI 요청에는 실명 대신 호칭만 쓰고,
  실명(앞 낱말)이 사연에 나오면 자동으로 막습니다.
- **화자는 언제나 '나'**입니다. 실제 경험에서 '누구 이야기인가요?'를 고르면 "제 와이프 이야기인데요"처럼 관계로 시작해 씁니다.
  인물 화면의 실제 사건에서 바로 경험을 만들 수 있습니다 ('실제로 있었던 일' 확인 후 사연에 씀).
- **실제 사건 → 경험으로 모두 옮기기**: 인물 화면 위쪽 버튼(또는 인물마다 버튼)으로 관계도 연표의 실제 사건(대화·통화로 확인한 것)을
  한 번에 **'실제로 있었던 일'로 확인된 경험**으로 만듭니다. 관계도 연표는 사용자가 확인한 실제 사건이라 따로 검수하지 않고 바로 사연 재료로 씁니다.
  가상(〔사연〕)·임의 사건은 옮기지 않고, 이미 옮긴 사건은 다시 만들지 않습니다.
- **사연처럼 풀어 쓰기**: 옮기면 곧바로 뒤에서 Claude API로 사건 한 줄을 사연처럼 풀어 씁니다(8건씩, 136건이면 몇 분, 수천 원 수준).
  사실(사건 한 줄)은 바꾸지 않고 '바꾸면 안 되는 사실'로 남기며, 그 인물의 확인된 정보(나이·직업·성격 등, 〔임의〕 정보 제외)와
  나의 마음·배경·마무리로만 살을 붙입니다. 새 사건·장소·숫자·대사는 만들지 않고, AI가 재료에 없는 내용을 넣었다고 표시하거나
  실명·연락처가 들어가면 원래 한 줄을 그대로 둡니다. 진행 상황은 **내 정보 → 실제 경험** 위쪽에 보입니다
  (진행 중이면 20초마다 새로 고침, 실행기가 꺼졌으면 '멈춤'과 실행 기록 끝부분·다시 시작 버튼, 끝나면 결과 수).
- 사연 로그(`.jsonl`)는 **사연 보관함**에 들어갑니다. 원본 사연을 각색한 **가상 사연은 그대로는 보내지 않고** AI 사연 초안의 재료로도 쓰지 않습니다.
  인물에게 실제로 비슷한 일이 있었다면 사연을 열어 **실제 있었던 일로 옮기기**를 누릅니다. '확인 전' 경험으로 복사되며(인물·시기·신청곡 포함),
  실제와 다르게 적힌 부분을 고치고 *"실제로 있었던 일"* 을 체크해야 사연으로 보냅니다.
  보관함 위쪽의 **경험으로 모두 가져오기 (확인 전)** 로 한 번에 가져올 수도 있습니다. 이때도 모두 '확인 전'이라 보내지 않고,
  하나씩 열어 고치고 체크한 것만 보냅니다 (실제 경험 목록에서 '확인 전 보관함 사연만 보기').
- 인물·사연 정보는 이 PC의 데이터 폴더에만 저장됩니다 (GitHub에 올리지 않음).

### 키워드 · 채팅창 교차 분석
- 키워드: **퀴즈·정답·오답·힌트**(퀴즈) / **사연·신청곡·게시판**(사연) / **선물**(선물). 자막에서 색으로 강조됩니다.
- 키워드가 들리면 그때부터 **채팅창에 올라오는 글도 10초마다 찍어** 모으고(설정 → 앱 채팅 → ④ 채팅창 영역 지정),
  분석할 때 녹취와 함께 Claude에 보내 교차 확인합니다. 받아쓰기가 틀린 낱말·문제·힌트·오늘의 주제를 채팅 글로 바로잡습니다.
  사진은 분석 한 번에 첫 장 + 최근 2장(장당 수백 토큰)만 보내고 저장하지 않습니다(마지막 한 장만 확인용으로 이 PC에 남김).
  다른 창에 가려져 있어도 앱 창만 따로 찍습니다 (최소화하면 못 찍음). 영역을 지정하지 않으면 녹취만으로 분석합니다.
- 힌트가 나오면 같은 문제로 묶어 다시 분석하고, 답이 더 확실해졌으면 아직 안 보낸 문제를 새 답으로 보냅니다.

### 기발한 오답
- 라디오 퀴즈는 정답만 뽑히지 않으므로, 분석할 때 **웃긴 포인트가 있는 오답**을 함께 만듭니다. 웃긴 포인트가 없거나 기발함 점수가 낮으면(기본 0.7 미만) 쓰지 않습니다.
- 보낼 답 고르기: 진행자가 재밌는 오답을 환영하거나 정답이 불확실하면 기발한 오답, 정답이 확실하면 기본 30%만 기발한 오답(설정 '기발한 오답 비율').
- 개인 사연을 지어내지 않고, 비하·정치·선정적인 농담은 쓰지 않습니다. 청취 화면 **기발한 오답 섞기**로 끌 수 있습니다.

### 사연: 채팅창 / 게시판
- 기본은 채팅창(앱 채팅 또는 문자)입니다. 진행자가 **'게시판에만'** 받는다고 하면 채팅으로 보내지 않고, 그 프로그램 게시판용 원고(제목·본문)를
  **원고 검토함**에 만듭니다. 게시판 등록은 로그인·보안 문자가 있어 원고 확인 후 '실제 화면에 입력하기' → 등록 버튼은 직접 누릅니다.
- 진행자가 신청곡도 받으면, 실제 경험이나 내 정보에 적어 둔 신청곡만 붙입니다 (지어내지 않음).

### 채널과 보내는 방법
- **앱 채팅**: 채널에 맞는 앱으로 보냅니다 (SBS → 고릴라, MBC → mini, KBS → 콩). 세 앱은 원리가 같아서 **설정 → 앱 채팅**에서 앱마다
  입력칸·전송 버튼을 네모로 한 번씩 지정하고 전송 테스트를 하면 됩니다.
- **휴대폰 문자**: PC에 USB로 연결한 안드로이드 휴대폰의 기본 문자 앱으로 보냅니다. 받는 번호가 작성 화면에 '#'까지 그대로 보일 때만 전송 버튼을 누릅니다.
  끝에 방송용 이름(내 정보)을 붙입니다. 준비 방법은 **설정 → 휴대폰 문자 설정**에 있습니다 (USB 디버깅, Google platform-tools).
  기본 번호: 파워FM #1077 · 러브FM #1035 · MBC FM4U #8000 · KBS 쿨FM #8910 · KBS 해피FM #1061 (KBS 1라디오 등 모르는 번호는 직접 입력).
- 확인 대기 글은 **앱 채팅으로 보내기 / 문자로 보내기** 중 골라 보낼 수 있습니다. 진행자가 '문자로만 받는다'고 하면 앱 채팅 자동 전송은 멈추고 확인 대기에 남습니다.
- 앱 창이나 휴대폰이 연결되지 않았으면 보낼 글을 보류했다가, 찾으면 보냅니다 (20분이 지나면 늦어서 확인 대기로 남김).

### 받아쓰기 테스트
첫 화면의 **🎤 받아쓰기 테스트 (10초)** 는 녹음 장치 → 10초 녹음(소리 크기) → 음성 인식 모델 → 받아쓰기를 차례로 해 보고 단계별 결과를 보여 줍니다.
진행자가 말할 때 눌러 보세요. 도중에 프로그램이 꺼지면 어느 단계에서 멈췄는지 남습니다.
- 고릴라 창을 찾지 못해도 **듣기·자막은 계속**합니다. 보낼 정답·사연은 1분마다 고릴라 창을 다시 찾아, 찾으면 보냅니다(20분 넘게 지난 것은 늦어서 보내지 않음).
- 선택 항목: *퀴즈 정답 자동 전송* · *사연 자동 전송*(검사 경고가 없는 글만) · *선물 정보 기록* · *자막 창 띄우기*.
- 이전 버전은 **예약 시간에만** 들었기 때문에 예약이 없으면 음성 인식이 전혀 돌지 않았습니다. 예약은 이제 선택(설정 화면)입니다.

### 퀴즈
1. 스피커로 나가는 소리를 10초 단위로 녹음하고(마이크 아님), 이 PC에서 무료 음성 인식(faster-whisper)으로 글자로 바꿉니다. **오디오는 저장하지 않습니다.**
   - 귀로 들리는 소리가 아니라 윈도우가 스피커로 **보내는 신호**를 받습니다. 그래서 **스피커 음소거(작업 표시줄 스피커 아이콘)** 를 해도 받아쓸 수 있습니다.
   - 반대로 **고릴라 앱 안 볼륨**이나 윈도우 '볼륨 믹서'의 **고릴라 볼륨**을 0으로 하거나 고릴라를 멈추면 신호 자체가 없어 받아쓸 수 없습니다. 둘은 최대로 두세요.
   - 윈도우 전체 볼륨 막대를 낮췄을 때 녹음 크기가 줄어드는지는 PC(소리 장치)마다 다릅니다. **받아쓰기 테스트**의 '소리 크기'로 확인하세요. 작게 들어오면 받아쓰기 전에 자동으로 최대 100배까지 키웁니다.
   - 소리를 듣기 싫으면 볼륨을 내리지 말고 **음소거**를 쓰는 것이 가장 확실합니다.
2. '퀴즈·정답·초성·문제 나갑니다' 같은 말이 들리면 40초 더 듣고, 최근 3분 자막을 **Claude API**로 보내 문제·정답·응모 방법을 정리합니다.
3. 아래 조건을 **모두** 만족하면 고릴라 공감로그 입력칸에 정답을 넣고 전송합니다. 못 채우면 **퀴즈 기록 → 확인 대기**에 남기고, **이 답으로 보내기**를 누르면 보냅니다.
   - *퀴즈 정답 자동 전송* 을 켰음, 정답 확신도가 기준(기본 0.8, 설정에서 변경) 이상
   - 진행자가 '문자로만'처럼 고릴라가 아닌 방법을 말하지 않음 (청취 모드는 모든 채널의 고릴라 응모를 열어 둠)
   - 최근 1시간 전송이 상한(기본 4건) 미만, 일괄 중지 꺼짐
4. 같은 문제를 다시 안내하면 한 건으로 묶고, 정답 발표는 새 문제로 보지 않습니다. **한 번 보냈거나 보냈는지 모르는 문제는 다시 보내지 않습니다.**
5. 정답 인정·당첨·상품 수령은 **퀴즈 기록**의 표에서 바로 기록합니다.

### 사연 (공감로그)
- 진행자가 "오늘의 주제는 ○○, 사연 보내 주세요"처럼 주제를 주면, '실제로 있었던 일'로 확인한 내 경험 중 맞는 것을 골라 공감로그용 200자 이내 글을 만듭니다. 맞는 경험이 없으면 쓰지 않고 주제만 알려 줍니다(직접 써서 보낼 수 있음). **없는 일을 지어내지 않습니다.**
- Claude에 보내기 전 '공개하지 않을 단어'와 경험별 '가릴 내용'은 ○○로 가립니다. 개인정보·재료에 없는 소재·숫자·인용을 검사합니다.
- *사연 자동 전송* 을 켜면 **검사 경고가 하나도 없는 글만** 바로 보냅니다. 경고가 있거나 AI가 경험에 없는 내용을 넣었다고 표시하면 **사연 → 확인 대기**에 남깁니다. 직접 써 둔 '공감로그용 한 줄'은 언제나 그대로 보냅니다.
- 한 번 보낸 경험은 **같은 방송국(SBS·MBC·KBS)에 다시 보내지 않습니다.** 다른 방송국에는 보낼 수 있습니다 (예: SBS 파워FM에 보낸 경험은
  러브FM·SBS 게시판에는 다시 안 쓰고, MBC·KBS에는 씀). 보냈는지 모르는 글(결과 불명)도 보낸 것으로 봅니다.
- **사연 → 보낸 사연 목록**: 앱 채팅·문자·게시판으로 보낸 글을 방송국별로 모아 보고, 경험마다 어느 방송국에 보냈는지(✓) 표로 봅니다.
- 확인할 글이 생기면 메뉴에 건수가 빨갛게 표시되고 알림음이 납니다.

### 선물 기록
- '선물·경품·기프티콘·추첨·당첨' 같은 말이 들리면 선물 이름, 받는 조건, 참여 방법, 마감, 당첨 인원, 발표 방법을 **선물 기록** 화면에 채널·프로그램별로 모읍니다. 같은 선물을 다시 안내하면 한 줄로 묶습니다.

### 특징·경험 가져오기
- Claude와의 대화에서 특징과 경험을 정리한 **가져오기 파일(.json)**을 받아 *실제 경험 → 가져오기*로 한 번에 넣을 수 있습니다. 가져온 경험은 '실제로 있었던 일' 확인이 꺼진 채 들어가므로 읽고 체크해야 쓰입니다.

### 처음 설정 (첫 화면 '준비 상태'에 빠진 항목이 표시됨)
1. **Claude API 키** — [Claude Console](https://platform.claude.com/)에서 발급한 키를 **설정** 화면에 저장합니다. 윈도우 자격 증명 관리자에만 저장되고 화면·기록·GitHub에는 남지 않습니다. (또는 환경 변수 `ANTHROPIC_API_KEY`)
2. **환경 점검** — 녹음 장치·고릴라 창·구성 요소·API 키가 잡히는지 확인합니다.
3. **고릴라·인식 설정** — 고릴라에서 듣는 채널의 공감로그 화면을 열어 두고 *① 입력칸 영역 지정* (화면이 어두워지면 '공감로그 글쓰기' 칸을 마우스로 끌어 네모) → *② 전송 버튼 영역 지정* → *③ 전송 테스트* ('파워 FM 화이팅'을 입력하고 **전송까지 실제로 누름**, 글은 설정값에서 변경 가능).
   각 단계 직후 고릴라 영역을 찍은 **확인용 사진**이 같은 화면에 나옵니다. ③ '누르기 직전' 사진에서 빨간 점이 입력칸, 초록 점이 전송 버튼 위에 있고 '보낸 뒤' 사진의 채팅에 글이 보이면 맞습니다.
   엉뚱한 곳에 있으면 *고릴라 창 영역 지정*으로 창 전체를 네모로 감싼 뒤 ①②를 다시 합니다.
4. **실제 경험** — 사연을 보내려면 **내 정보 → 실제 경험**에 적고 '실제로 있었던 일'을 체크합니다(없으면 퀴즈만 동작).
5. 관리 화면 창(검은 창)이 열려 있고 PC가 켜져 있는 동안 동작합니다. 절전 모드에 들어가지 않게 해 두세요.
6. (선택) **예약** — 설정 화면에서 프로그램·요일·시간을 정하면 청취 시작을 누르지 않아도 그 시간에 듣습니다.

### 비용·주의
- Claude API는 유료입니다. 퀴즈·사연·선물 신호가 들릴 때만 호출하고, 프로그램(또는 예약)당 분석 횟수 상한(퀴즈 15·사연 4·선물 4회)을 둡니다. 호출 1회는 보통 수십 원 수준입니다 (모델은 고릴라·인식 설정에서 변경 가능).
- 녹음은 PC에서 나는 모든 소리를 받으므로, 청취 중에는 다른 소리를 꺼 두는 것이 좋습니다.
- 전송하는 순간 고릴라 창이 잠깐 앞으로 나왔다가 원래 창으로 돌아갑니다.
- SBS가 자동 참여를 허용하는지는 확인되지 않았습니다. 약관상 제한(도배·운영 방해 등)이나 계정 제재·당첨 무효의 위험은 사용자에게 있습니다.
- 고릴라 PC 앱의 화면 구조는 공개되어 있지 않아 이 저장소에서는 실제 앱으로 시험하지 못했습니다. 처음에는 *전송 테스트* 사진과, 자동 전송을 끈 '확인 대기'로 동작을 확인하세요.

## 안전장치

- **확인 안 된 조건 = 대기**: 모집 중 확인, 공지 확인 기록, 마감, 제출 대상 지정, 사용자 승인, 사실 확인, 실제 경험 확인 중 하나라도 없으면 실제 화면 입력 버튼이 꺼집니다.
- **첫 대상은 '사연과 신청곡' 한 곳**만 제출 대상으로 지정되어 있습니다.
- **한 경험은 방송국마다 한 번**: 같은 경험이 *입력만 함 / 등록 확인 / 결과 불명* 상태로 같은 방송국 이력에 있으면 다시 보내지 않습니다 (게시판은 SBS).
- **결과 불명은 재전송하지 않음**: 입력 후 글쓰기 화면을 벗어나면 *결과 불명* 으로 기록하고, 게시판 확인 전까지 같은 경험을 막습니다.
- **공지 변경 감지**: 붙여 둔 공지 원문이 바뀌면 재검토 전 제출 중지.
- **일괄 중지**: 설정 화면 버튼 하나로 모든 입력 작업을 막습니다.
- **입력 직렬화**: 입력 작업은 한 번에 하나만 실행됩니다.
- **허용 주소**: 실제 입력은 `https://programs.sbs.co.kr`, `https://m.programs.sbs.co.kr` 글쓰기 화면에서만 합니다.
- **로컬 전용 화면**: 관리 화면은 127.0.0.1에서만 열리고, 외부 사이트가 보낸 위조 요청은 거부합니다.

## 데이터

- 모든 데이터는 프로그램 폴더 밖의 데이터 폴더(SQLite 파일)에 저장됩니다. 윈도우: `C:\Users\<이름>\AppData\Local\RadioHelper`
  (검은 창 첫 화면과 **설정** 화면에 위치가 나옵니다). **개인 경험이 들어 있으니 GitHub나 채팅에 올리지 마세요.**
- 백업은 데이터 폴더의 `radio_helper.sqlite3` 파일을 복사하면 됩니다.
- 글쓰기 화면·고릴라 창 점검 보고서는 데이터 폴더의 `inspect/`, 실행 기록은 `logs/` 에 남습니다.
- 개발·시험용으로 다른 위치를 쓰려면 환경 변수 `RADIO_HELPER_DATA_DIR` 를 지정합니다.
- 방송 녹취(글자)는 데이터베이스에 남고, 오디오는 저장하지 않습니다.

## 다음 단계 (아직 하지 않음)

- 실제 1건 제출 결과를 보고 SBS 글쓰기 화면에 맞춘 입력 설정을 확정
- 고릴라: 실제 고릴라 PC 앱의 전송 테스트 사진을 보고 입력 방식(화면 요소/위치) 확정, 며칠간 '확인 대기'로 정확도 확인
- 러브FM·고릴라M 편성: 사용자 PC에서 '공식 페이지에서 새로고침'으로 채우기
- 사연 게시판 자동 등록은 SBS 최신 약관·코너별 공지 확인 전까지 켜지 않습니다.

## 개발

```bash
python -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m pytest
```

모의 화면 종단 테스트는 Chromium이 있으면 실행됩니다 (`RADIO_HELPER_CHROMIUM=/path/to/chrome`).
퀴즈 자동 참여는 가짜 녹음·인식·분석·고릴라로 예약 구간과 '청취 시작' 전체를 돌리는 테스트가 있습니다 (`tests/test_quizbot.py`, `tests/test_live.py`).
윈도우 전용 부분(`quizbot/audio.py` 녹음, `quizbot/gorilla.py` 화면 조작, `quizbot/captions.py` 자막 창)은 실제 PC에서만 동작합니다.
